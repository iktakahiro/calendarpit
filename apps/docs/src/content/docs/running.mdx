Calendarpit serves the API, OAuth, and admin UI from one origin. See [Installation](/calendarpit/installation/) for prerequisites, supported platforms, and 0.9.0 publication status. The commands below use the packaged distribution; no source checkout or build is needed.

## Ways to run Calendarpit

### npm and the installed CLI

Start with Node.js 22 or later:

```sh
npx @iktakahiro/calendarpit@0.9.0 serve
```

Pass options directly after the package name, for example `npx @iktakahiro/calendarpit@0.9.0 serve --database :memory: --port 0`. If you installed with Homebrew or put a standalone executable on your `PATH`, use `calendarpit` instead:

```sh
calendarpit serve --port 4173
calendarpit serve --port 0 --database :memory:
```

These are alternative startup commands; run one server per database file. Port `0` lets the OS choose an available port. Read the actual URLs in the startup output:

```text
Calendarpit data: :memory:

Calendarpit v0.9.0
Data   :memory:
Admin  http://127.0.0.1:38425/
API    http://127.0.0.1:38425/calendar/v3
Health http://127.0.0.1:38425/__calendarpit/health
```

The packaged executable includes the server, admin UI assets, and Bun runtime. npm needs Node.js for its launcher; Homebrew and standalone downloads need neither Node.js nor Bun. Stop the server with Ctrl+C.

### Docker and Compose

```sh
docker run --rm \
  -p 127.0.0.1:4173:4173 \
  -v calendarpit-data:/data \
  ghcr.io/iktakahiro/calendarpit:0.9.0
```

The container runs as a non-root user with `CALENDARPIT_HOST=0.0.0.0` and `CALENDARPIT_PORT=4173`. SQLite is stored at `/data/calendarpit.sqlite`. The published host port stays on loopback. Add environment variables with `-e` before the image name, or CLI flags after it:

```sh
docker run --rm -p 127.0.0.1:4173:4173 \
  ghcr.io/iktakahiro/calendarpit:0.9.0 serve --database :memory:
```

See [Installation](/calendarpit/installation/) for a Compose service, health checks, and host/container addresses. Use [Fixtures](/calendarpit/fixtures/) to mount a startup configuration. Source development instructions live in the [development guide](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md).

## Command-line options and environment variables

The CLI syntax is `calendarpit [serve] [options]`. The `serve` subcommand is optional. Unknown commands, unknown flags, or invalid option values print an error to `stderr` and exit with code `1`.

Command-line flags take precedence over environment variables.

| CLI option          | Environment variable   | Default                           | Description                                                                                                                                                                                                            |
| ------------------- | ---------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--host <host>`     | `CALENDARPIT_HOST`     | `127.0.0.1`                       | Bind address. Non-loopback addresses (`0.0.0.0`, `::`) must be set explicitly.                                                                                                                                         |
| `-p`, `--port <n>`  | `CALENDARPIT_PORT`     | `4173`                            | Listen port (`0`–`65535`). Use `0` to let the OS choose a free port; the assigned port appears in the startup output. Avoid `4175` if you also run the reference sample app.                                           |
| `--database <path>` | `CALENDARPIT_DATABASE` | `.calendarpit/calendarpit.sqlite` | SQLite database file path, or `:memory:` for a disposable in-memory session. See [Storage and restarts](/calendarpit/storage/).                                                                                        |
| `--config <path>`   | `CALENDARPIT_CONFIG`   | Built-in fixture                  | Path to a JSON startup fixture. The file must exist and contain valid JSON. Seeds a new database or `:memory:` session; silently ignored when opening an existing SQLite file. See [Fixtures](/calendarpit/fixtures/). |
| `-h`, `--help`      | —                      | —                                 | Print help and exit.                                                                                                                                                                                                   |
| `-v`, `--version`   | —                      | —                                 | Print `0.9.0` and exit.                                                                                                                                                                                                |

### Additional environment variables

| Environment variable      | Default       | Description                                                                                                                                                                                                                                              |
| ------------------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CALENDARPIT_WATCH_HOSTS` | Loopback only | Comma-separated extra hostnames allowed as `events.watch` and `calendarList.watch` webhook targets (for example, `host.docker.internal` when running in Docker). Environment variable only; no CLI flag. See [Watch notifications](/calendarpit/watch/). |

### Loopback binding and working directory

- **Loopback by default**: Calendarpit binds to `127.0.0.1` unless you pass `--host` or `CALENDARPIT_HOST`. The admin UI and [test control API](/calendarpit/test-control/) have no authentication, so binding to `0.0.0.0` exposes them to other machines on your network.
- **Relative paths**: With npm, Homebrew, and standalone executables, paths in `--database` and `--config` (or their environment variables) resolve from the directory where you start Calendarpit. Run it from your project directory or use absolute paths. Docker uses paths inside the container; mount host files before referencing them. See [Troubleshooting](/calendarpit/troubleshooting/) for common startup errors.

## Admin UI

The admin UI is served at the root of the same origin as the API (`http://127.0.0.1:4173/` by default). It polls `GET /__calendarpit/state` and request history every 2 seconds so changes made by your app appear automatically. Use the left rail to switch the selected test user and calendar (`?user=<id>&calendar=<id>`) and to check whether storage is `SQLite` or `In-memory`.

The admin UI loads the Roboto Mono font from Google Fonts (`fonts.googleapis.com` and `fonts.gstatic.com`) and falls back to system fonts when offline. Calendar API and OAuth operations never contact Google and need no internet access.

| Route          | Section         | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`            | **Schedule**    | View stored events in day or week mode (default date `2026-10-19`). Create, edit, and delete events (summary, all-day toggle, start/end, busy/free status, location, description, and extended properties JSON). A recurring series appears once, at its first occurrence, and is not expanded. Saving an event in the editor replaces it with the fields the form shows. Attendees, reminders, colors, and other fields set through the Calendar API are removed, and a recurring event loses its `recurrence`. Use the Calendar API to edit those events. |
| `/users`       | **Users**       | List, create, edit, and delete test users. Deleting a user also deletes their calendars and events, and revokes their OAuth connections (which also stops their watch channels).                                                                                                                                                                                                                                                                                                                                                                            |
| `/calendars`   | **Calendars**   | List, create, edit, and delete calendars for the selected test user, set the IANA time zone (default `Asia/Tokyo`), and choose the primary calendar.                                                                                                                                                                                                                                                                                                                                                                                                        |
| `/connections` | **Connections** | Inspect active and revoked OAuth grants by test user and OAuth client, and revoke active grants (which also stops their watch channels). See [Local OAuth](/calendarpit/oauth/).                                                                                                                                                                                                                                                                                                                                                                            |
| `/watch`       | **Watch**       | Read-only view of active watch channels and the webhook delivery log. See [Watch notifications](/calendarpit/watch/).                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `/history`     | **API history** | Inspect, filter by text or show only HTTP `>= 400` errors, and clear the latest 200 Calendar API and OAuth exchanges with masked credentials.                                                                                                                                                                                                                                                                                                                                                                                                               |
| `/settings`    | **Settings**    | Switch the theme (**Appearance**), view the storage path, load a fixture JSON file, reset the workspace to its reset baseline, inspect the current state JSON (**Test data**), or view registered OAuth clients and redirect URIs (**OAuth clients**).                                                                                                                                                                                                                                                                                                      |
