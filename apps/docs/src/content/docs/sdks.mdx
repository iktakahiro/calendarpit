Keep your application's Google Calendar operations and point its SDK client at
Calendarpit. The examples below list calendars and call FreeBusy through the
official Google clients. No Calendarpit-specific SDK is required.

## Before you call the SDK

Start Calendarpit with `bun run dev`, then complete [local OAuth](/calendarpit/integration/#complete-local-oauth)
using the `https://www.googleapis.com/auth/calendar` scope. Set
`CALENDARPIT_ACCESS_TOKEN` to the resulting access token in your local shell.
These examples read that variable explicitly; it is not a Google SDK setting.

<Aside>
  These snippets use an already-issued access token to demonstrate Calendar API
  routing. They do not implement authorization callbacks or automatic refresh.
  Refresh through Calendarpit's `/oauth/token`, then replace the client's token
  or recreate the client. The [Bun sample](/calendarpit/integration/)
  demonstrates the complete authorization, refresh, revocation, and reconnection
  lifecycle.
</Aside>

Use dependencies pinned in your application's lockfile. Package names are listed
in each tab; Calendarpit does not install these language runtimes or SDKs for you.

## Configure the service URL

Endpoint formats differ across libraries. Preserve trailing slashes where shown.

| Language                | SDK setting                             | Value                                     |
| ----------------------- | --------------------------------------- | ----------------------------------------- |
| TypeScript / JavaScript | `rootUrl`                               | `http://127.0.0.1:4173/`                  |
| Python                  | `client_options.api_endpoint`           | `http://127.0.0.1:4173/calendar/v3/`      |
| Go                      | `option.WithEndpoint`                   | `http://127.0.0.1:4173/calendar/v3/`      |
| Java                    | `setRootUrl` + `setServicePath`         | `http://127.0.0.1:4173/` + `calendar/v3/` |
| C# / .NET               | `BaseClientService.Initializer.BaseUri` | `http://127.0.0.1:4173/calendar/v3/`      |

Every FreeBusy example sends `POST /calendar/v3/freeBusy` to Calendarpit. Event
CRUD and calendar-list calls on the same client use that local service URL too.
Only [implemented operations](/calendarpit/compatibility/) are supported, even if the SDK
exposes additional methods.

## List calendars and query FreeBusy

<Tabs>
<TabItem label="TypeScript / JavaScript">

Packages: `@googleapis/calendar` and `google-auth-library`. Run with Bun; the same
JavaScript works in a Node.js ESM application. The monolithic `googleapis` package
also accepts `google.calendar({ version: 'v3', auth, rootUrl })`.

```ts
import { calendar } from '@googleapis/calendar';
import { OAuth2Client } from 'google-auth-library';

const token = process.env.CALENDARPIT_ACCESS_TOKEN;
if (!token) throw new Error('Set CALENDARPIT_ACCESS_TOKEN first.');

const auth = new OAuth2Client();
auth.setCredentials({ access_token: token });
const api = calendar({
  version: 'v3',
  auth,
  rootUrl: 'http://127.0.0.1:4173/',
});

const calendars = await api.calendarList.list();
console.log(calendars.data.items);

const { data } = await api.freebusy.query({
  requestBody: {
    timeMin: '2026-10-19T00:00:00+09:00',
    timeMax: '2026-10-20T00:00:00+09:00',
    timeZone: 'Asia/Tokyo',
    items: [{ id: 'primary' }],
  },
});
console.log(data.calendars?.primary?.busy ?? []);
```

This access-token-only client cannot refresh. For full OAuth, use the local
`endpoints` configuration in [Connect your application](/calendarpit/integration/#javascript-oauth-client).
The repository's executable sample uses that configuration and blocks outbound
requests to non-loopback hosts.

Reference: [Google Calendar Node.js client implementation](https://github.com/googleapis/google-api-nodejs-client/blob/main/src/apis/calendar/v3.ts).

</TabItem>
<TabItem label="Python">

Packages: `google-api-python-client` (2.x) and `google-auth`.
`static_discovery=True` uses the discovery document bundled with the installed
library, so constructing the client does not fetch discovery metadata from Google.
The endpoint includes the entire Calendar service path.

```python
import os

from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build

credentials = Credentials(token=os.environ["CALENDARPIT_ACCESS_TOKEN"])
with build(
    "calendar",
    "v3",
    credentials=credentials,
    static_discovery=True,
    cache_discovery=False,
    client_options={
        "api_endpoint": "http://127.0.0.1:4173/calendar/v3/",
    },
) as api:
    print(api.calendarList().list().execute().get("items", []))
    result = api.freebusy().query(body={
        "timeMin": "2026-10-19T00:00:00+09:00",
        "timeMax": "2026-10-20T00:00:00+09:00",
        "timeZone": "Asia/Tokyo",
        "items": [{"id": "primary"}],
    }).execute()
    print(result["calendars"]["primary"]["busy"])
```

If you later add a refresh token to `Credentials`, also supply the registered
client ID, client secret, and `token_uri="http://127.0.0.1:4173/oauth/token"`.
Authorization and user-info URLs still belong to your application's OAuth flow.

References: [bundled discovery documents](https://googleapis.github.io/google-api-python-client/docs/start.html#building-and-calling-a-service),
[endpoint selection](https://github.com/googleapis/google-api-python-client/blob/main/googleapiclient/discovery.py).

</TabItem>
<TabItem label="Go">

Modules: `google.golang.org/api` and `golang.org/x/oauth2`.
Supply an explicit token source so the client does not try to discover Google
application-default credentials.

```go
package main

import (
    "context"
    "fmt"
    "log"
    "os"

    "golang.org/x/oauth2"
    "google.golang.org/api/calendar/v3"
    "google.golang.org/api/option"
)

func main() {
    token := os.Getenv("CALENDARPIT_ACCESS_TOKEN")
    if token == "" {
        log.Fatal("Set CALENDARPIT_ACCESS_TOKEN first.")
    }
    api, err := calendar.NewService(context.Background(),
        option.WithEndpoint("http://127.0.0.1:4173/calendar/v3/"),
        option.WithTokenSource(oauth2.StaticTokenSource(&oauth2.Token{
            AccessToken: token,
            TokenType: "Bearer",
        })),
    )
    if err != nil { log.Fatal(err) }

    calendars, err := api.CalendarList.List().Do()
    if err != nil { log.Fatal(err) }
    fmt.Println(calendars.Items)

    result, err := api.Freebusy.Query(&calendar.FreeBusyRequest{
        TimeMin: "2026-10-19T00:00:00+09:00",
        TimeMax: "2026-10-20T00:00:00+09:00",
        TimeZone: "Asia/Tokyo",
        Items: []*calendar.FreeBusyRequestItem{{Id: "primary"}},
    }).Do()
    if err != nil { log.Fatal(err) }
    fmt.Println(result.Calendars["primary"].Busy)
}
```

For SDK-managed OAuth, configure `oauth2.Config.Endpoint.AuthURL` and `TokenURL`
with Calendarpit's authorization and token URLs, set `AuthStyle` to
`oauth2.AuthStyleInParams`, and pass `config.TokenSource(ctx, token)` instead of
`StaticTokenSource`. The static source above intentionally never refreshes.

References: [Calendar client](https://pkg.go.dev/google.golang.org/api/calendar/v3),
[WithEndpoint](https://pkg.go.dev/google.golang.org/api/option#WithEndpoint),
[OAuth configuration](https://pkg.go.dev/golang.org/x/oauth2#Config).

</TabItem>
<TabItem label="Java">

Artifacts: `com.google.apis:google-api-services-calendar`,
`com.google.http-client:google-http-client`, and
`com.google.http-client:google-http-client-gson`. Use compatible pinned versions
in Maven or Gradle. This example uses Java 11 or newer.

```java
import com.google.api.client.http.javanet.NetHttpTransport;
import com.google.api.client.json.gson.GsonFactory;
import com.google.api.client.util.DateTime;
import com.google.api.services.calendar.Calendar;
import com.google.api.services.calendar.model.FreeBusyRequest;
import com.google.api.services.calendar.model.FreeBusyRequestItem;
import java.util.List;

public class CalendarpitExample {
    public static void main(String[] args) throws Exception {
        String token = System.getenv("CALENDARPIT_ACCESS_TOKEN");
        if (token == null || token.isBlank()) {
            throw new IllegalStateException("Set CALENDARPIT_ACCESS_TOKEN first.");
        }
        Calendar api = new Calendar.Builder(
            new NetHttpTransport(),
            GsonFactory.getDefaultInstance(),
            request -> request.getHeaders().setAuthorization("Bearer " + token)
        )
            .setRootUrl("http://127.0.0.1:4173/")
            .setServicePath("calendar/v3/")
            .setApplicationName("Calendarpit local example")
            .build();

        System.out.println(api.calendarList().list().execute().getItems());
        FreeBusyRequest body = new FreeBusyRequest()
            .setTimeMin(new DateTime("2026-10-19T00:00:00+09:00"))
            .setTimeMax(new DateTime("2026-10-20T00:00:00+09:00"))
            .setTimeZone("Asia/Tokyo")
            .setItems(List.of(new FreeBusyRequestItem().setId("primary")));
        var result = api.freebusy().query(body).execute();
        System.out.println(result.getCalendars().get("primary").getBusy());
    }
}
```

The request initializer supplies the bearer token without starting another OAuth
flow. Obtain and refresh it using the [local OAuth endpoints](/calendarpit/integration/#complete-local-oauth).
Changing `setRootUrl` does not redirect a separate Google authorization helper.

References: [Calendar builder](https://googleapis.dev/java/google-api-services-calendar/latest/com/google/api/services/calendar/Calendar.Builder.html),
[FreeBusy request](https://googleapis.dev/java/google-api-services-calendar/latest/com/google/api/services/calendar/model/FreeBusyRequest.html).

<TabItem label="C#">

NuGet packages: `Google.Apis.Calendar.v3` and `Google.Apis.Auth`.
Use this in a console application supporting top-level statements.

```csharp
using System;
using System.Collections.Generic;
using Google.Apis.Auth.OAuth2;
using Google.Apis.Calendar.v3;
using Google.Apis.Calendar.v3.Data;
using Google.Apis.Services;

var token = Environment.GetEnvironmentVariable("CALENDARPIT_ACCESS_TOKEN");
if (string.IsNullOrWhiteSpace(token))
    throw new InvalidOperationException("Set CALENDARPIT_ACCESS_TOKEN first.");

using var api = new CalendarService(new BaseClientService.Initializer
{
    BaseUri = "http://127.0.0.1:4173/calendar/v3/",
    HttpClientInitializer = GoogleCredential.FromAccessToken(token),
    ApplicationName = "Calendarpit local example",
});

var calendars = await api.CalendarList.List().ExecuteAsync();
foreach (var calendar in calendars.Items)
    Console.WriteLine(calendar.Id);

var result = await api.Freebusy.Query(new FreeBusyRequest
{
    TimeMinRaw = "2026-10-19T00:00:00+09:00",
    TimeMaxRaw = "2026-10-20T00:00:00+09:00",
    TimeZone = "Asia/Tokyo",
    Items = new List<FreeBusyRequestItem>
    {
        new FreeBusyRequestItem { Id = "primary" },
    },
}).ExecuteAsync();

foreach (var interval in result.Calendars["primary"].Busy)
    Console.WriteLine($"{interval.StartRaw} - {interval.EndRaw}");
```

`FromAccessToken` does not refresh tokens. Use the [local token endpoint](/calendarpit/integration/#complete-local-oauth)
and recreate the credentials after refreshing. `BaseUri` configures Calendar API
requests only; it does not redirect OAuth helpers.

References: [service base URI](https://cloud.google.com/dotnet/docs/reference/Google.Apis/latest/Google.Apis.Services.BaseClientService.Initializer),
[access-token credentials](https://docs.cloud.google.com/dotnet/docs/reference/Google.Apis/latest/Google.Apis.Auth.OAuth2.GoogleCredential),
[FreeBusy request](https://googleapis.dev/dotnet/Google.Apis.Calendar.v3/latest/api/Google.Apis.Calendar.v3.Data.FreeBusyRequest.html).

</TabItem>
<TabItem label="HTTP / curl">

Use the same protocol from any language with an HTTP client.

```sh
curl --fail-with-body http://127.0.0.1:4173/calendar/v3/users/me/calendarList \
  -H "Authorization: Bearer $CALENDARPIT_ACCESS_TOKEN"

curl --fail-with-body http://127.0.0.1:4173/calendar/v3/freeBusy \
  -H "Authorization: Bearer $CALENDARPIT_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{
    "timeMin": "2026-10-19T00:00:00+09:00",
    "timeMax": "2026-10-20T00:00:00+09:00",
    "timeZone": "Asia/Tokyo",
    "items": [{"id": "primary"}]
  }'
```

`primary` resolves to the main calendar of the authorized test user. For Alex in
the default fixture, this query returns a busy interval from 10:00 to 11:00 on
October 19, 2026 in Asia/Tokyo. Changing events in the admin UI changes the next
FreeBusy response; free and deleted events do not contribute busy time.

## Verification and troubleshooting

The Bun/TypeScript sample has an automated HTTP E2E covering OAuth, calendar
selection, event CRUD, FreeBusy, watch, refresh, revocation, denial, and reset.
Python, Go, Java, and C# examples are based on the linked official client APIs;
they have not yet been compiled or executed in this repository's CI. Treat them
as integration recipes, not a claim that every SDK version has been certified.

| Symptom                                                   | Check                                                                                           |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| A real Google consent screen appears                      | The application's authorization URL still points to Google.                                     |
| Refresh contacts Google                                   | Configure the OAuth token endpoint separately from the Calendar service URL.                    |
| `404` or a repeated `/calendar/v3/` path                  | Compare the SDK's endpoint format with the table above.                                         |
| `401` after reset or revocation                           | Obtain a new Calendarpit token by authorizing again.                                            |
| Python fetches discovery from Google                      | Use 2.x and keep `static_discovery=True`; do not set a remote discovery URL.                    |
| Watch succeeds but the app does not receive notifications | Check the callback's reachability from Calendarpit and the [delivery log](/calendarpit/watch/). |

Inspect **API history** in the admin UI to see the received method, path, status,
and masked payload. In isolated E2E runs, restrict outbound traffic to your local
test services so an overlooked default endpoint cannot reach Google. The bundled
sample already guards its SDK transport this way.
