Point your app's official Google Calendar SDK client at Calendarpit. You do not need a Calendarpit-specific SDK.

The examples below list calendars and query FreeBusy.

## Before you call the SDK

Prepare an access token and the SDK packages first:

1. Start Calendarpit, for example with `calendarpit serve`. See [Run and configure](/running/).
2. Complete the [local OAuth flow](/oauth/) with the `https://www.googleapis.com/auth/calendar` scope. If you need a refresh token, add `access_type=offline`.
3. Set `CALENDARPIT_ACCESS_TOKEN` in your shell to the resulting access token. The token is valid for one hour.
4. Install the packages listed in each tab in your project. Calendarpit does not install language runtimes or SDK packages for you.

The examples read `CALENDARPIT_ACCESS_TOKEN` directly. It is not a Google SDK setting.

<Callout>

These snippets pass an existing access token. They show how to route Calendar API requests to Calendarpit.

- They do not handle authorization callbacks or automatic token refresh.
- To refresh tokens, call `POST /oauth/token`. Then update the client's token or recreate the client.

See [Connect your app](/connect/) for the sample app and full OAuth client configuration.

</Callout>

## Configure the service URL

Each library expects a different endpoint format.

- Preserve trailing slashes where shown.
- If Calendarpit runs on another host or port, replace `127.0.0.1:4173` in every value.

| Language                | SDK setting                             | Value                                     |
| ----------------------- | --------------------------------------- | ----------------------------------------- |
| TypeScript / JavaScript | `rootUrl`                               | `http://127.0.0.1:4173/`                  |
| Python                  | `client_options.api_endpoint`           | `http://127.0.0.1:4173/calendar/v3/`      |
| Go                      | `option.WithEndpoint`                   | `http://127.0.0.1:4173/calendar/v3/`      |
| Kotlin                  | `setRootUrl` + `setServicePath`         | `http://127.0.0.1:4173/` + `calendar/v3/` |
| PHP                     | `Calendar` constructor `$rootUrl`       | `http://127.0.0.1:4173/`                  |
| C# / .NET               | `BaseClientService.Initializer.BaseUri` | `http://127.0.0.1:4173/calendar/v3/`      |

Every FreeBusy example sends `POST /calendar/v3/freeBusy` to Calendarpit. Event CRUD and calendar-list calls on the same client also use that local URL.

For `calendarList`, these methods are supported: `list`, `get`, `insert`, `patch`, `update`, `delete`, and `watch`. The single-owner limits in [Calendar API compatibility](/compatibility/) apply.

<Callout type="warn">

Only the operations listed in [Calendar API compatibility](/compatibility/) are supported, even if the SDK exposes more methods.

</Callout>

## List calendars and query FreeBusy

<Tabs items={["TypeScript / JavaScript","Python","Go","Kotlin","PHP","C#","HTTP / curl"]}>
<Tab value="TypeScript / JavaScript" forceMount>

- **Packages**: `@googleapis/calendar` and `google-auth-library`.
- **Runtime**: Bun, or Node.js 22 or later as an ES module (`.mjs`).
- **Monolithic package**: `googleapis` also accepts `google.calendar({ version: 'v3', auth, rootUrl })`.

```ts
import { calendar } from '@googleapis/calendar';
import { OAuth2Client } from 'google-auth-library';

const token = process.env.CALENDARPIT_ACCESS_TOKEN;
if (!token) throw new Error('Set CALENDARPIT_ACCESS_TOKEN first.');

const auth = new OAuth2Client();
auth.setCredentials({ access_token: token });
const api = calendar({
  version: 'v3',
  auth,
  rootUrl: 'http://127.0.0.1:4173/',
});

const calendars = await api.calendarList.list();
console.log(calendars.data.items);

const { data } = await api.freebusy.query({
  requestBody: {
    timeMin: '2026-10-19T00:00:00+09:00',
    timeMax: '2026-10-20T00:00:00+09:00',
    timeZone: 'Asia/Tokyo',
    items: [{ id: 'primary' }],
  },
});
console.log(data.calendars?.primary?.busy ?? []);
```

This access-token-only client cannot refresh tokens. For full OAuth setup, use the local `endpoints` configuration shown in [Connect your app](/connect/).

Reference: [Google Calendar Node.js client implementation](https://github.com/googleapis/google-api-nodejs-client/blob/main/src/apis/calendar/v3.ts).

</Tab>
<Tab value="Python" forceMount>

- **Packages**: `google-api-python-client` (2.x) and `google-auth`.
- **Discovery**: `static_discovery=True` uses the discovery document bundled with the installed library. Building the client therefore does not fetch discovery metadata from Google.
- **Endpoint**: `api_endpoint` includes the `/calendar/v3/` path.

```python
import os

from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build

credentials = Credentials(token=os.environ["CALENDARPIT_ACCESS_TOKEN"])
with build(
    "calendar",
    "v3",
    credentials=credentials,
    static_discovery=True,
    cache_discovery=False,
    client_options={
        "api_endpoint": "http://127.0.0.1:4173/calendar/v3/",
    },
) as api:
    print(api.calendarList().list().execute().get("items", []))
    result = api.freebusy().query(body={
        "timeMin": "2026-10-19T00:00:00+09:00",
        "timeMax": "2026-10-20T00:00:00+09:00",
        "timeZone": "Asia/Tokyo",
        "items": [{"id": "primary"}],
    }).execute()
    print(result["calendars"]["primary"]["busy"])
```

If you pass a refresh token to `Credentials`:

- Also supply the registered client ID, client secret, and `token_uri="http://127.0.0.1:4173/oauth/token"`.
- Omit `scopes`, or pass the exact granted scopes in the same order.

Configure the authorization, userinfo, and revocation URLs separately in your app's [OAuth flow](/oauth/).

References: [bundled discovery documents](https://googleapis.github.io/google-api-python-client/docs/start.html#building-and-calling-a-service), [endpoint selection](https://github.com/googleapis/google-api-python-client/blob/main/googleapiclient/discovery.py).

<Tab value="Go" forceMount>

- **Modules**: `google.golang.org/api` and `golang.org/x/oauth2`.
- **Credentials**: Supply an explicit token source. This keeps the client from looking up Google Application Default Credentials.

```go
package main

import (
	"context"
	"fmt"
	"log"
	"os"

	"golang.org/x/oauth2"
	"google.golang.org/api/calendar/v3"
	"google.golang.org/api/option"
)

func main() {
	token := os.Getenv("CALENDARPIT_ACCESS_TOKEN")
	if token == "" {
		log.Fatal("Set CALENDARPIT_ACCESS_TOKEN first.")
	}
	api, err := calendar.NewService(context.Background(),
		option.WithEndpoint("http://127.0.0.1:4173/calendar/v3/"),
		option.WithTokenSource(oauth2.StaticTokenSource(&oauth2.Token{
			AccessToken: token,
			TokenType:   "Bearer",
		})),
	)
	if err != nil {
		log.Fatal(err)
	}

	calendars, err := api.CalendarList.List().Do()
	if err != nil {
		log.Fatal(err)
	}
	for _, c := range calendars.Items {
		fmt.Println(c.Id)
	}

	result, err := api.Freebusy.Query(&calendar.FreeBusyRequest{
		TimeMin:  "2026-10-19T00:00:00+09:00",
		TimeMax:  "2026-10-20T00:00:00+09:00",
		TimeZone: "Asia/Tokyo",
		Items:    []*calendar.FreeBusyRequestItem{{Id: "primary"}},
	}).Do()
	if err != nil {
		log.Fatal(err)
	}
	for _, b := range result.Calendars["primary"].Busy {
		fmt.Println(b.Start, "-", b.End)
	}
}
```

`StaticTokenSource` never refreshes tokens. For SDK-managed OAuth:

1. Set `oauth2.Config.Endpoint.AuthURL` and `TokenURL` to Calendarpit's [OAuth endpoints](/oauth/).
2. Pass `config.TokenSource(ctx, token)`.

References: [Calendar client](https://pkg.go.dev/google.golang.org/api/calendar/v3), [WithEndpoint](https://pkg.go.dev/google.golang.org/api/option#WithEndpoint), [OAuth configuration](https://pkg.go.dev/golang.org/x/oauth2#Config).

<Tab value="Kotlin" forceMount>

- **Artifacts**: `com.google.apis:google-api-services-calendar`, `com.google.http-client:google-http-client`, and `com.google.http-client:google-http-client-gson`.
- **Runtime**: Kotlin/JVM with JDK 11 or later. The example calls the Google API Client Library for Java from Kotlin.

```kotlin
import com.google.api.client.http.javanet.NetHttpTransport
import com.google.api.client.json.gson.GsonFactory
import com.google.api.client.util.DateTime
import com.google.api.services.calendar.Calendar
import com.google.api.services.calendar.model.FreeBusyRequest
import com.google.api.services.calendar.model.FreeBusyRequestItem

fun main() {
    val token = System.getenv("CALENDARPIT_ACCESS_TOKEN")
    require(!token.isNullOrBlank()) { "Set CALENDARPIT_ACCESS_TOKEN first." }

    val api = Calendar.Builder(
        NetHttpTransport(),
        GsonFactory.getDefaultInstance(),
    ) { request -> request.headers.setAuthorization("Bearer $token") }
        .setRootUrl("http://127.0.0.1:4173/")
        .setServicePath("calendar/v3/")
        .setApplicationName("Calendarpit local example")
        .build()

    println(api.calendarList().list().execute().items)

    val body = FreeBusyRequest()
        .setTimeMin(DateTime("2026-10-19T00:00:00+09:00"))
        .setTimeMax(DateTime("2026-10-20T00:00:00+09:00"))
        .setTimeZone("Asia/Tokyo")
        .setItems(listOf(FreeBusyRequestItem().setId("primary")))
    val result = api.freebusy().query(body).execute()
    println(result.calendars["primary"]?.busy)
}
```

The request initializer lambda sets the bearer token header directly. Obtain and refresh tokens using the [local OAuth endpoints](/oauth/).

Setting `setRootUrl` does not redirect separate Google authorization helpers.

References: [Calendar builder](https://googleapis.dev/java/google-api-services-calendar/latest/com/google/api/services/calendar/Calendar.Builder.html), [FreeBusy request](https://googleapis.dev/java/google-api-services-calendar/latest/com/google/api/services/calendar/model/FreeBusyRequest.html).

<Tab value="PHP" forceMount>

- **Composer package**: `google/apiclient` (2.x).
- **Runtime**: PHP 8.1 or later, run from the project directory that contains `vendor/`.
- **Root URL**: The second `Calendar` constructor argument is the origin. The service appends `calendar/v3/`.

```php
<?php

require __DIR__ . '/vendor/autoload.php';

use Google\Client;
use Google\Service\Calendar;
use Google\Service\Calendar\FreeBusyRequest;
use Google\Service\Calendar\FreeBusyRequestItem;

$token = getenv('CALENDARPIT_ACCESS_TOKEN');
if ($token === false || $token === '') {
    throw new RuntimeException('Set CALENDARPIT_ACCESS_TOKEN first.');
}

$client = new Client();
$client->setApplicationName('Calendarpit local example');
$client->setAccessToken($token);
$api = new Calendar($client, 'http://127.0.0.1:4173/');

foreach ($api->calendarList->listCalendarList()->getItems() as $calendar) {
    echo $calendar->getId(), PHP_EOL;
}

$item = new FreeBusyRequestItem();
$item->setId('primary');
$request = new FreeBusyRequest();
$request->setTimeMin('2026-10-19T00:00:00+09:00');
$request->setTimeMax('2026-10-20T00:00:00+09:00');
$request->setTimeZone('Asia/Tokyo');
$request->setItems([$item]);

$result = $api->freebusy->query($request);
foreach ($result->getCalendars()['primary']->getBusy() as $interval) {
    echo $interval->getStart(), ' - ', $interval->getEnd(), PHP_EOL;
}
```

`setAccessToken` with only an access token does not refresh it. Refresh via the [local token endpoint](/oauth/), then call `setAccessToken` again.

The `$rootUrl` argument configures Calendar API requests only. OAuth helpers on `Google\Client`, such as `fetchAccessTokenWithAuthCode`, still target Google.

References: [PHP client library](https://github.com/googleapis/google-api-php-client), [Calendar service](https://github.com/googleapis/google-api-php-client-services/blob/main/src/Calendar.php).

<Tab value="C#" forceMount>

- **NuGet packages**: `Google.Apis.Calendar.v3` and `Google.Apis.Auth`.
- **Project type**: A console application with top-level statements.

```csharp
using System;
using System.Collections.Generic;
using Google.Apis.Auth.OAuth2;
using Google.Apis.Calendar.v3;
using Google.Apis.Calendar.v3.Data;
using Google.Apis.Services;

var token = Environment.GetEnvironmentVariable("CALENDARPIT_ACCESS_TOKEN");
if (string.IsNullOrWhiteSpace(token))
    throw new InvalidOperationException("Set CALENDARPIT_ACCESS_TOKEN first.");

using var api = new CalendarService(new BaseClientService.Initializer
{
    BaseUri = "http://127.0.0.1:4173/calendar/v3/",
    HttpClientInitializer = GoogleCredential.FromAccessToken(token),
    ApplicationName = "Calendarpit local example",
});

var calendars = await api.CalendarList.List().ExecuteAsync();
foreach (var calendar in calendars.Items)
    Console.WriteLine(calendar.Id);

var result = await api.Freebusy.Query(new FreeBusyRequest
{
    TimeMinRaw = "2026-10-19T00:00:00+09:00",
    TimeMaxRaw = "2026-10-20T00:00:00+09:00",
    TimeZone = "Asia/Tokyo",
    Items = new List<FreeBusyRequestItem>
    {
        new FreeBusyRequestItem { Id = "primary" },
    },
}).ExecuteAsync();

foreach (var interval in result.Calendars["primary"].Busy)
    Console.WriteLine($"{interval.StartRaw} - {interval.EndRaw}");
```

`FromAccessToken` does not refresh tokens. Refresh via the [local token endpoint](/oauth/), then recreate the credentials.

`BaseUri` configures Calendar API requests only. It does not redirect OAuth helpers.

References: [service base URI](https://docs.cloud.google.com/dotnet/docs/reference/Google.Apis/latest/Google.Apis.Services.BaseClientService.Initializer), [access-token credentials](https://docs.cloud.google.com/dotnet/docs/reference/Google.Apis/latest/Google.Apis.Auth.OAuth2.GoogleCredential), [FreeBusy request](https://googleapis.dev/dotnet/Google.Apis.Calendar.v3/latest/api/Google.Apis.Calendar.v3.Data.FreeBusyRequest.html).

</Tab>
<Tab value="HTTP / curl" forceMount>

You can call the same HTTP endpoints directly from any language.

```sh
curl --fail-with-body http://127.0.0.1:4173/calendar/v3/users/me/calendarList \
  -H "Authorization: Bearer $CALENDARPIT_ACCESS_TOKEN"

curl --fail-with-body http://127.0.0.1:4173/calendar/v3/freeBusy \
  -H "Authorization: Bearer $CALENDARPIT_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{
    "timeMin": "2026-10-19T00:00:00+09:00",
    "timeMax": "2026-10-20T00:00:00+09:00",
    "timeZone": "Asia/Tokyo",
    "items": [{"id": "primary"}]
  }'
```

### Expected result

`primary` resolves to the primary calendar of the authenticated test user.

For Alex in the default fixture, this query returns one busy interval: `10:00` to `11:00` on October 19, 2026, in `Asia/Tokyo`.

Editing events in the admin UI changes the next FreeBusy response. Transparent and cancelled events do not count as busy time.
