## Why Calendarpit

Building apps and AI agents that use Google Calendar means setting up OAuth and preparing test data. With a live calendar, repeating a test from the same state can be hard. Calendarpit lets you test locally with fixtures and no Google credentials.

<Cards>
  <Card title="Testing with real Google">

    - Needs a Google account, Cloud project, and OAuth setup.
    - Depends on internet access and shared API quotas.
    - Shared calendar data changes between test runs.

  </Card>
  <Card title="Testing with Calendarpit">

    - Sign in as a local test user with no real credentials.
    - Runs on 127.0.0.1 in one process with no network access.
    - Seed data from fixtures and reset state between tests.

  </Card>
</Cards>

## How it works

<Steps>

<Step>

### Start Calendarpit

One process serves the API, local OAuth, and the admin UI on `http://127.0.0.1:4173`.

<Tabs items={["Docker","Homebrew"]} groupId='install'>
  <Tab value='Docker' forceMount>

```sh
docker run --rm -p 127.0.0.1:4173:4173 ghcr.io/iktakahiro/calendarpit:latest
```

</Tab>
  <Tab value='Homebrew' forceMount>

```sh
brew install iktakahiro/tap/calendarpit
calendarpit serve
```

</Tab>
</Tabs>

</Step>

<Step>

### Point your app to Calendarpit

Keep your Google SDK and override its OAuth and API endpoints. For example, with `@googleapis/calendar` and `google-auth-library`:

```ts
const origin = 'http://127.0.0.1:4173';
const auth = new OAuth2Client({
  clientId: 'sample-app',
  clientSecret: 'local-sample-secret',
  redirectUri: 'http://127.0.0.1:4175/callback',
  endpoints: {
    oauth2AuthBaseUrl: `${origin}/oauth/authorize`,
    oauth2TokenUrl: `${origin}/oauth/token`,
  },
});
const api = calendar({ version: 'v3', auth, rootUrl: origin });
```

[Connect your app](/connect/) covers every endpoint, and [SDK examples](/sdks/) cover Python, Go, Kotlin, PHP, and .NET.

</Step>

<Step>

### Test with fixtures

Reset to the startup fixture before each test, and inspect requests in the admin UI.

```sh
curl -X POST http://127.0.0.1:4173/__calendarpit/reset \
  -H "Content-Type: application/json" \
  -d '{}'
```

</Step>

</Steps>

## Inside the admin UI

The admin UI is served on the same origin as the API (`http://127.0.0.1:4173/`). Open it in the browser while your app runs to check events written through the Calendar API, inspect requests and webhook deliveries, and edit test data between runs.
