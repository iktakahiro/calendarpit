## Calendar API

Every supported `/calendar/v3` endpoint requires a Calendarpit bearer token (see [Local OAuth](/oauth/) for scopes). Access is limited to calendars owned by the authorized test user, and `primary` resolves to that user's primary calendar. Unknown or unowned calendar IDs return `404` (`notFound`); `freebusy.query` instead reports a per-calendar `notFound` error inside a `200` response.

| Method                  | Path                                                             | Behavior                                                                                 |
| ----------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| GET                     | `/calendar/v3/users/me/calendarList`                             | Owned calendars; `maxResults`, `pageToken`, `minAccessRole`, `showDeleted`, `showHidden` |
| POST                    | `/calendar/v3/users/me/calendarList`                             | Restore an owned calendar to the list                                                    |
| GET, PUT, PATCH, DELETE | `/calendar/v3/users/me/calendarList/{calendarId}`                | Read, replace, patch, or remove a calendar-list entry                                    |
| POST                    | `/calendar/v3/users/me/calendarList/watch`                       | Subscribe to calendar-list changes                                                       |
| GET                     | `/calendar/v3/calendars/{calendarId}`                            | Calendar metadata (`id`, `summary`, `timeZone`)                                          |
| GET, POST               | `/calendar/v3/calendars/{calendarId}/events`                     | List or create events                                                                    |
| GET, PUT, PATCH, DELETE | `/calendar/v3/calendars/{calendarId}/events/{eventId}`           | Read, replace, patch, or delete an event                                                 |
| GET                     | `/calendar/v3/calendars/{calendarId}/events/{eventId}/instances` | Recurring instances and exceptions                                                       |
| POST                    | `/calendar/v3/freeBusy`                                          | Merged, clipped busy ranges, up to 50 calendars                                          |
| POST                    | `/calendar/v3/calendars/{calendarId}/events/watch`               | Subscribe to event changes                                                               |
| POST                    | `/calendar/v3/channels/stop`                                     | Stop an event or calendar-list watch channel                                             |

### Method coverage

Unrouted endpoints return `501` (`unsupportedFeature`). `calendars.update`, `calendars.patch`, and `calendars.delete` check the token, scope, and calendar ownership first (`401`, `403`, or `404`), then return `501`. Because `events.import` and `events.quickAdd` share `/events/{eventId}`, `events.import` returns `404` (`notFound`), while `events.quickAdd` returns `400` (`unsupportedFeature`) with `text` or `404` without it. Unsupported HTTP methods on the events collection or an existing event return `405` (`methodNotAllowed`).

## Events

Supported event fields are `id`, `summary`, `description`, `location`, `start`, `end`, `transparency` (`opaque`, `transparent`), `status` (`confirmed`, `tentative`, `cancelled`), `visibility` (`default`, `public`, `private`, `confidential`), `colorId` (`"1"`–`"11"`), `attendees`, `attendeesOmitted`, `guestsCanModify`, `guestsCanInviteOthers`, `guestsCanSeeOtherGuests`, `reminders`, `recurrence`, `conferenceData` (requires `conferenceDataVersion=1`), `hangoutLink`, and `extendedProperties.private` / `extendedProperties.shared` string maps. Write endpoints accept `sendUpdates` (`all`, `externalOnly`, `none`) and `conferenceDataVersion` (`0`, `1`). Event IDs allow `[a-zA-Z0-9@._-]{1,128}` (except `primary`); duplicate IDs return `409` (`duplicate`).

Responses include `organizer`, `creator`, `iCalUID`, `sequence`, `created`, `updated`, and a quoted `etag`. Write requests also accept `kind`, `etag`, `created`, `updated`, `calendarId` (the resolved calendar ID, not `primary`), and `sequence`, so a fetched event can be sent back unchanged. `organizer`, `creator`, `iCalUID`, `recurringEventId`, and `originalStartTime` are read-only, but updates accept unchanged values. On `events.insert`, omit these fields; Calendarpit sets them. `sequence` increments on each update. `If-Match` is checked on `GET`, `PUT`, `PATCH`, and `DELETE` of stored events (`412` `conditionNotMet` on mismatch).

`PUT` replaces writable fields and resets omitted optional fields to defaults; `PATCH` preserves omitted fields. On `PATCH`, a supplied `start` or `end` object replaces the stored object (its fields are not merged), and `extendedProperties` maps merge by key (`null` removes a key or map). All-day inputs accept `dateTime: null` and `timeZone: null`. `events.delete` returns `204` and keeps a `cancelled` tombstone (`410` `deleted` if already cancelled). `events.get` returns tombstones, `freebusy.query` excludes them, and lists exclude them unless `showDeleted=true` or `updatedMin` is set (cancelled exceptions of a series stay visible with `singleEvents=false`). See [Events, recurrence and time](/recurrence/) for recurrence, invitations, reminders, synthetic Meet links, and time rules.

## Calendar list

### Entry shape

- Calendar-list entries use `kind: "calendar#calendarListEntry"`. `list` and `get` return the same entry shape.
- Each owned calendar starts on its owner's list with `accessRole: "owner"`, `selected: true`, `colorId: "1"` (`backgroundColor: "#ac725e"`, `foregroundColor: "#1d1d1d"`), `defaultReminders: []`, `primary`, and `conferenceProperties.allowedConferenceSolutionTypes: ["hangoutsMeet"]`.
- `hidden` is omitted unless `true`. `summaryOverride` and `notificationSettings` are omitted when empty. `deleted: true` appears only on removed or tombstoned entries.
- `description` and `location` are omitted and rejected (`400` `unsupportedFeature`).
- Writes accept read-only fields (`kind`, `etag`, `id`, `summary`, `timeZone`, `accessRole`, `primary`, `deleted`, `conferenceProperties`) only when unchanged (`400` `invalidParameter` on mismatch; `id` accepts `primary` when the path uses `primary`).
- `etag` updates when entry settings or the calendar's `summary`, `timeZone`, or `primary` flag changes.
- `If-Match` is checked on `PATCH`, `PUT`, and `DELETE` (`412` `conditionNotMet`).

### Writing settings (patch, update, insert)

- Writable per-user settings (`summaryOverride`, `colorId`, `backgroundColor`, `foregroundColor`, `hidden`, `selected`, `defaultReminders`, `notificationSettings`) persist across SQLite restarts and clear on reset or fixture load.
- `summaryOverride` requires a non-blank string up to 10,000 characters (`""` returns `400`).
- `PATCH` preserves omitted writable fields (`null` clears `summaryOverride`, `defaultReminders`, and `notificationSettings`).
- `PUT` and `insert` (`200`) replace writable fields: omitted overrides, reminders, and notifications are cleared, `hidden` and `selected` reset to `false` (never-written entries stay `selected: true`), and `colorId` resets to `"1"` unless colors are supplied.
- Unchanged writes return `200` without changing the `etag`, invalidating calendar-list page tokens, or notifying watch channels.

### Colors

- `colorId` accepts palette IDs `"1"`–`"24"` (foreground `"#1d1d1d"`; unknown IDs or inherited names like `"constructor"` return `400`).
- With `colorRgbFormat=true`, every `insert`, `patch`, or `update` must include both `backgroundColor` and `foregroundColor` (`#rrggbb`), or it returns `400`. Any supplied `colorId` is ignored and set to the nearest palette color.
- Without `colorRgbFormat=true`, RGB fields may only repeat the displayed colors. On `PATCH`, repeating the current `colorId` and RGB keeps custom colors. `PUT` and `insert` must send `colorRgbFormat=true` to keep custom RGB colors. A different `colorId` clears custom RGB.

### Reminders and notifications

- `defaultReminders` accepts up to 5 `{method: "email" | "popup", minutes: 0–40320}` items.
- `notificationSettings.notifications` accepts up to 5 `{method: "email", type}` items with unique `type` values (`eventCreation`, `eventChange`, `eventCancellation`, `eventResponse`, `agenda`; duplicate types return `400`).
- Neither setting sends email.
- `PATCH {"notificationSettings": {}}` keeps existing notifications, while `[]`, `null`, or `PUT` without `notifications` clears them.
- Ignoring `colorId` with `colorRgbFormat=true` and preserving notifications on `PATCH {"notificationSettings": {}}` follow Google's reference docs and were not checked against live Google.

### Delete and insert

- `calendarList.delete` (`204`) removes a non-primary calendar from the caller's list only (`403` `cannotDeletePrimaryCalendar` for the primary calendar; `404` if already removed).
- The calendar and its events remain accessible to `calendars.get`, `events.*`, `freebusy.query`, and `events.watch`, while `calendarList.get`, `patch`, and `update` return `404`.
- `calendarList.insert` requires `id` (`400` if missing) and restores a removed owned calendar (`200`). It never creates a calendar, and already-listed calendars (including hidden ones and `primary`) return `409` (`duplicate`; unhide with `patch`).
- Deleting a primary calendar via the management API promotes the first remaining listed calendar, or restores the first owned calendar to the list with its saved settings if all were removed.
- Setting `primary: true` via the management API also restores a removed calendar to the list.

### Watch

- `calendarList.watch` shares the loopback allowlist, delivery log, and `channels.stop` endpoint with `events.watch` (see [Watch notifications](/watch/)).
- It sends `sync` on open, then `exists` when a list write changes stored settings or when the management API creates, updates, or deletes the user's calendars. Event writes do not trigger it.
- Other query parameters (including `syncToken`) and `params` (such as `params.ttl`) return `400` (`unsupportedFeature`).

## Lists and paging

`calendarList.list` accepts `maxResults`, `pageToken`, `minAccessRole` (`freeBusyReader`, `reader`, `writer`, `owner`), `showDeleted`, and `showHidden`, and returns a collection `etag` (no `nextSyncToken`). All owned calendars have the `owner` role, so every valid `minAccessRole` matches them. `showHidden` defaults to `false` and omits `hidden: true` entries from `list` (`get` still returns them). `showDeleted=true` includes `deleted: true` entries for calendars removed with `calendarList.delete` (keeping their stored settings, even if `hidden: true`) and tombstones of calendars deleted via the management API (using default list settings, and keeping `primary: true` if the deleted calendar was primary).

`events.list` accepts `timeMin`, `timeMax`, `maxResults` (1–2500, default 250), `pageToken`, `orderBy` (`startTime`, `updated`), `singleEvents`, `timeZone`, `showDeleted`, `syncToken`, `updatedMin`, `iCalUID`, and repeatable `privateExtendedProperty=name=value` and `sharedExtendedProperty=name=value` filters (all must match). `orderBy=startTime` requires `singleEvents=true`; unordered lists sort by event ID. `timeMin`, `timeMax`, and `updatedMin` require RFC 3339 timestamps with an offset, and matching uses `start < timeMax` and `end > timeMin`. If a calendar has an unbounded recurring series, `events.list` requires `timeMax` whenever `singleEvents=true` or `timeMin` is set, and `events.instances` on that series always requires `timeMax` (`400` `unsupportedFeature`).

Event list pages freeze a snapshot on the first page so writes between pages do not skip items. Event page tokens are query- and user-bound, expire after 1 hour, and clear on restart, reset, or fixture load. Calendar-list page tokens invalidate on any data or calendar-list write and are not persisted. Expired or stale tokens return `410` (`invalidPageToken`). See [Incremental sync](/sync/) for `syncToken` and `nextSyncToken`.

## Explicit exclusions

ACLs, shared calendars, delegation, calendar groups, color palettes (`colors.get`), user settings, calendar-list sync tokens, ACL and settings watch, free-text search (`q`), `eventTypes`, attachments, real email delivery, real Google Meet creation, and full OIDC are unsupported. Unknown body fields return `400` (`unsupportedFeature`). Unknown query parameters, including `fields`, return `400` (`unsupportedFeature`) on every `/calendar/v3` endpoint except `channels.stop`, which ignores its query string. Transport parameters (`alt=json`, `prettyPrint`, `quotaUser`, `key`) are accepted, but API keys never replace OAuth bearer tokens. Calendarpit never proxies to or syncs with Google. To manage calendars and reset data, see [Test control API](/test-control/); to point a client at Calendarpit, see [Connect your app](/connect/).
