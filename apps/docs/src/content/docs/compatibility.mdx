## Calendar API

Every supported `/calendar/v3` endpoint requires a Calendarpit bearer token (see [Local OAuth](/calendarpit/oauth/) for scopes). Access is limited to calendars owned by the authorized test user, and `primary` resolves to that user's primary calendar. Unknown or unowned calendar IDs return `404` (`notFound`); `freebusy.query` instead reports a per-calendar `notFound` error inside a `200` response.

| Method                  | Path                                                             | Behavior                                                                   |
| ----------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| GET                     | `/calendar/v3/users/me/calendarList`                             | Owned calendars; `maxResults`, `pageToken`, `minAccessRole`, `showDeleted` |
| GET                     | `/calendar/v3/calendars/{calendarId}`                            | Calendar metadata (`id`, `summary`, `timeZone`)                            |
| GET, POST               | `/calendar/v3/calendars/{calendarId}/events`                     | List or create events                                                      |
| GET, PUT, PATCH, DELETE | `/calendar/v3/calendars/{calendarId}/events/{eventId}`           | Read, replace, patch, or delete an event                                   |
| GET                     | `/calendar/v3/calendars/{calendarId}/events/{eventId}/instances` | Recurring instances and exceptions                                         |
| POST                    | `/calendar/v3/freeBusy`                                          | Merged, clipped busy ranges, up to 50 calendars                            |
| POST                    | `/calendar/v3/calendars/{calendarId}/events/watch`               | Subscribe to event changes                                                 |
| POST                    | `/calendar/v3/channels/stop`                                     | Stop a watch channel                                                       |

### Method coverage

Unrouted endpoints return `501` (`unsupportedFeature`). `calendars.update`, `calendars.patch`, and `calendars.delete` check the token, scope, and calendar ownership first (`401`, `403`, or `404`), then return `501`. Because `events.import` and `events.quickAdd` share `/events/{eventId}`, `events.import` returns `404` (`notFound`), while `events.quickAdd` returns `400` (`unsupportedFeature`) with `text` or `404` without it. Unsupported HTTP methods on the events collection or an existing event return `405` (`methodNotAllowed`).

## Events

Supported event fields are `id`, `summary`, `description`, `location`, `start`, `end`, `transparency` (`opaque`, `transparent`), `status` (`confirmed`, `tentative`, `cancelled`), `visibility` (`default`, `public`, `private`, `confidential`), `colorId` (`"1"`–`"11"`), `attendees`, `attendeesOmitted`, `guestsCanModify`, `guestsCanInviteOthers`, `guestsCanSeeOtherGuests`, `reminders`, `recurrence`, `conferenceData` (requires `conferenceDataVersion=1`), `hangoutLink`, and `extendedProperties.private` / `extendedProperties.shared` string maps. Write endpoints accept `sendUpdates` (`all`, `externalOnly`, `none`) and `conferenceDataVersion` (`0`, `1`). Event IDs allow `[a-zA-Z0-9@._-]{1,128}` (except `primary`); duplicate IDs return `409` (`duplicate`).

Responses include `organizer`, `creator`, `iCalUID`, `sequence`, `created`, `updated`, and a quoted `etag`. `kind`, `etag`, `created`, `updated`, `calendarId` (the resolved calendar ID, not `primary`), and `sequence` are also accepted, so a fetched event can be sent back unchanged. `organizer`, `creator`, `iCalUID`, `recurringEventId`, and `originalStartTime` are read-only, though unchanged values are accepted on updates. On `events.insert`, omit these fields; they are set by Calendarpit. `sequence` increments on each update. `If-Match` is checked on `GET`, `PUT`, `PATCH`, and `DELETE` of stored events (`412` `conditionNotMet` on mismatch).

`PUT` replaces writable fields and resets omitted optional fields to defaults; `PATCH` preserves omitted fields. On `PATCH`, a supplied `start` or `end` object replaces the stored object (its fields are not merged), and `extendedProperties` maps merge by key (`null` removes a key or map). All-day inputs accept `dateTime: null` and `timeZone: null`. `events.delete` returns `204` and keeps a `cancelled` tombstone (`410` `deleted` if already cancelled). `events.get` returns tombstones, `freebusy.query` excludes them, and lists exclude them unless `showDeleted=true` or `updatedMin` is set (cancelled exceptions of a series stay visible with `singleEvents=false`). See [Events, recurrence and time](/calendarpit/recurrence/) for recurrence, invitations, reminders, synthetic Meet links, and time rules.

## Lists and paging

`calendarList.list` accepts `maxResults`, `pageToken`, `minAccessRole` (`freeBusyReader`, `reader`, `writer`, `owner`), and `showDeleted`. All owned calendars have the `owner` role, so every valid `minAccessRole` matches them. Deleted calendars appear only with `showDeleted=true`.

`events.list` accepts `timeMin`, `timeMax`, `maxResults` (1–2500, default 250), `pageToken`, `orderBy` (`startTime`, `updated`), `singleEvents`, `timeZone`, `showDeleted`, `syncToken`, `updatedMin`, `iCalUID`, and repeatable `privateExtendedProperty=name=value` and `sharedExtendedProperty=name=value` filters (all must match). `orderBy=startTime` requires `singleEvents=true`; unordered lists sort by event ID. `timeMin`, `timeMax`, and `updatedMin` require RFC 3339 timestamps with an offset, and matching uses `start < timeMax` and `end > timeMin`. If a calendar has an unbounded recurring series, `events.list` requires `timeMax` whenever `singleEvents=true` or `timeMin` is set, and `events.instances` on that series always requires `timeMax` (`400` `unsupportedFeature`).

Event list pages freeze a snapshot on the first page so writes between pages do not skip items. Event page tokens are query- and user-bound, expire after 1 hour, and clear on restart, reset, or fixture load. Calendar-list page tokens invalidate on any data write. Expired or stale tokens return `410` (`invalidPageToken`). See [Incremental sync](/calendarpit/sync/) for `syncToken` and `nextSyncToken`.

## Explicit exclusions

ACLs, shared calendars, delegation, calendar groups, color palettes, user settings, calendar-list watch, free-text search (`q`), `eventTypes`, attachments, real email delivery, real Google Meet creation, and full OIDC are unsupported. Unknown body fields return `400` (`unsupportedFeature`). Unknown query parameters, including `fields`, return `400` (`unsupportedFeature`) on every `/calendar/v3` endpoint except `channels.stop`, which ignores its query string. Transport parameters (`alt=json`, `prettyPrint`, `quotaUser`, `key`) are accepted, but API keys never replace OAuth bearer tokens. Calendarpit never proxies to or syncs with Google. To manage calendars and reset data, see [Test control API](/calendarpit/test-control/); to point a client at Calendarpit, see [Connect your app](/calendarpit/connect/).
