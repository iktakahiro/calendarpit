Calendarpit expands recurring series, syncs invitations between local test users, and calculates time ranges and free/busy intervals locally. For supported endpoints and fields, see [Calendar API compatibility](/calendarpit/compatibility/).

## Recurrence

In `events.list`, `singleEvents=false` (default) returns series masters and stored exceptions; `singleEvents=true` expands occurrences.

`GET /calendar/v3/calendars/{calendarId}/events/{eventId}/instances` always returns expanded occurrences for one series (with `singleEvents=false`, cancelled exceptions appear without `showDeleted`). It accepts the `events.list` parameters (such as `timeMin`, `timeMax`, `showDeleted`, `maxResults`, `pageToken`, and `timeZone`) plus `originalStart`, rejects `syncToken`, and omits `nextSyncToken`.

Each instance carries `recurringEventId`, `originalStartTime`, and a deterministic ID (`<seriesId>_<YYYYMMDDTHHMMSSZ>` in UTC for timed events, or `<seriesId>_<YYYYMMDD>` for all-day events). On `/events/{instanceId}`, `GET` returns the occurrence even if no exception is stored; `PUT` and `PATCH` store it as an exception; `DELETE` stores a cancelled exception. Updating a master updates its instances and cancels stored exceptions the new rule no longer produces; deleting a master cancels its exceptions. With `singleEvents=true`, [incremental sync](/calendarpit/sync/) reports removed occurrences as `cancelled`. `freebusy.query` uses the same expansion.

### Rules, limits, and DST

`recurrence` accepts 1–20 `RRULE`, `EXRULE`, `RDATE`, or `EXDATE` lines (an empty array stores a non-recurring event). Other lines (such as `DTSTART`), missing or sub-daily `FREQ` (`HOURLY`, `MINUTELY`, `SECONDLY`), unlisted uppercase rule parts (such as `BYHOUR`), or duplicate rule parts return `400 unsupportedFeature`. Malformed parts or invalid values, combinations, or line counts return `400 invalidParameter`.

| Aspect              | Supported behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FREQ`              | `DAILY`, `WEEKLY`, `MONTHLY`, `YEARLY`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Rule parts          | `INTERVAL` (1–10000), `COUNT` (1–10000) or `UNTIL` (not both), `BYDAY` (`MO`–`SU`, optional `±1`–`5` on `MONTHLY`/`YEARLY`), `BYMONTHDAY` (`±1`–`31`), `BYMONTH` (`1`–`12`), `BYSETPOS` (`±1`–`366`), `WKST`                                                                                                                                                                                                                                                                                                                                                  |
| Time zone & `UNTIL` | Timed series require `start.timeZone`. Timed `UNTIL` must be UTC (`...Z`). All-day `UNTIL` is a date.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `RDATE` / `EXDATE`  | Timed series allow `;TZID=<zone>`. All-day series require `;VALUE=DATE`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Limits              | At most 10,000 instances per expansion (per request window, or for the whole series when there is no `timeMax`), and at most 100 years (366×100 days) from `DTSTART` for finite series expanded without `timeMax`, `timeMin`, and `timeMax` (`400 unsupportedFeature` if exceeded). Unbounded series (no `COUNT`/`UNTIL`) require `timeMax` when expanding (`singleEvents=true`) or when `timeMin` is passed to `events.list`. One series over a limit fails the whole list or `freeBusy` request. Deleted series still count; send `timeMax` or reset state. |
| DST                 | Rules keep wall-clock time in `start.timeZone`. Nonexistent local times (spring-forward gap) fail with `400 unsupportedFeature` when an expansion reaches the gap occurrence (`instances`, `events.list` with `singleEvents=true` or with `timeMin`/`timeMax`, instance IDs for occurrences within about two days of the gap, and `freeBusy`). The insert itself succeeds; the error fails the whole request. Ambiguous times (fall-back fold) use the earlier pre-transition offset, such as `-04:00` in New York.                                           |

## Invitations, reminders, and local meetings

Calendarpit never sends email or calls Google Meet.

- **Invitations:** `attendees` accepts up to 200 unique emails (`displayName`, `optional`, `resource`, `additionalGuests`, `comment`, and `responseStatus`: `needsAction`, `accepted`, `tentative`, `declined`). Inviting a local test user with a primary calendar writes a copy (same `id` and `iCalUID`) to that calendar. Organizer updates and cancellations propagate to copies and trigger [watch notifications](/calendarpit/watch/); removing an attendee cancels their copy. `reminders` and `extendedProperties.private` stay per-copy; `extendedProperties.shared` comes from the organizer.
- **RSVP and invitee edits:** Invitees must use `PATCH` (`PUT` returns `403 forbiddenForNonOrganizer`) and may only edit their own `responseStatus` and `comment` (or set `attendeesOmitted: true` with only their own entry), plus `reminders`, `colorId`, `transparency`, and `extendedProperties`. RSVP changes update the organizer and other copies (an RSVP to one instance of a series creates an exception in the organizer's calendar). Declining sets the invitee's copy to `transparent` (other `attendees` patches reset it to `opaque`). The next organizer update overwrites `colorId` and `transparency` changes on a copy.
- **Guest flags:** `guestsCanModify` (`false`), `guestsCanInviteOthers` (`true`), and `guestsCanSeeOtherGuests` (`true`) round-trip as booleans, and only the organizer can change them. They are stored only and do not change what invitees may edit.
- **`sendUpdates`:** `all` records one entry per write with all attendees except the organizer in `recipients` (including removed attendees; for an invitee's `REPLY`, the recipient is the organizer). `externalOnly` records only recipients who are not local users. Entries (`REQUEST`, `CANCEL`, or `REPLY`) appear in `GET /__calendarpit/state` under `notifications` (last 200; see [Test control API](/calendarpit/test-control/)). `none` (default) records nothing. Local copies sync regardless.
- **Reminders:** `{ useDefault: boolean, overrides?: [{ method: "email" | "popup", minutes: 0..40320 }] }` (max 5 overrides when `useDefault: false`). Stored only; never fired.
- **Conference data:** Non-null `conferenceData` requires `?conferenceDataVersion=1`. A `hangoutsMeet` `createRequest.requestId` generates a deterministic ID, `hangoutLink`, and a `video` entry point at `https://meet.calendarpit.invalid/<id>`. `conferenceData: null` clears it.

## Time semantics and free/busy

Event intervals are half-open `[start, end)`, with `end` after `start`. List filters match `start < timeMax` and `end > timeMin`, so adjacent events do not overlap.

- **All-day events:** `start.date` and exclusive `end.date` (`YYYY-MM-DD`) use midnight in the calendar's time zone, including on 23-hour and 25-hour DST days.
- **Timed events:** `dateTime` requires a UTC offset/`Z` or IANA `timeZone`. Unoffset local times in a DST gap or overlap return `400`. Responses format `dateTime` with a numeric offset in the requested `timeZone` (or the calendar's zone). The response's `timeZone` is also the requested or calendar zone, not the event's stored zone.
- **Free/busy (`POST /calendar/v3/freeBusy`):** Queries up to 50 calendars and returns busy ranges formatted in `timeZone` (default `UTC`). It expands recurring series, excludes `transparent` (free, including declined invitations) and `cancelled` (deleted) events, merges overlapping or adjacent intervals, and clips them to `[timeMin, timeMax)`. Unknown or unowned calendars return a per-calendar `notFound` error with `busy: []`.
