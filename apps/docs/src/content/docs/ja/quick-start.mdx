## Calendarpit を起動する

0.9.0 の配布物は準備中で、まだ公開されていません。公開状況とソースからの起動方法は[インストール](/calendarpit/ja/installation/)を参照してください。

公開後は Node.js 22 以降で実行できます。

```sh
npx @iktakahiro/calendarpit@0.9.0 serve
```

Docker を使用する場合:

```sh
docker run --rm \
  -p 127.0.0.1:4173:4173 \
  -v calendarpit-data:/data \
  ghcr.io/iktakahiro/calendarpit:0.9.0
```

Google アカウント、Google Cloud プロジェクト、外部データベース、`.env` ファイル、プロバイダーの認証情報は不要です。どちらのコマンドでも、API、ローカル OAuth サーバー、管理画面が同じオリジンで起動します。Homebrew、Compose、単体実行ファイル、プロジェクトへの追加は[インストール](/calendarpit/ja/installation/)で説明しています。

## 管理画面を開く

`http://127.0.0.1:4173` を開きます。組み込みの fixture にはテストユーザー `alex` と `sam`、3 つのカレンダー、`2026-10-19` の planning イベントが含まれます。API 経由の変更も自動で表示されます。

CLI は実行ディレクトリ内の `.calendarpit/calendarpit.sqlite` にデータを保存します。Docker はマウントしたボリュームに保存します。一時的なテストには、CLI で `--database :memory:`、Docker で `-e CALENDARPIT_DATABASE=:memory:` を指定してください。[ストレージと再起動](/calendarpit/ja/storage/)も参照してください。

## ヘルスエンドポイントを確認する

```sh
curl http://127.0.0.1:4173/__calendarpit/health
```

```json
{
  "name": "Calendarpit",
  "version": "0.9.0",
  "stage": "preview",
  "storage": "sqlite",
  "capabilities": {
    "calendar": true,
    "oauth": true,
    "watch": true,
    "fixtures": true
  }
}
```

0.9.0 はプレビュー版です。対応範囲はドキュメントに記載されていますが、1.0 までは API が変更される可能性があります。

## アプリを接続する

[アプリを接続する](/calendarpit/ja/connect/)に従って、SDK と OAuth フローの接続先を Calendarpit に変更します。[fixture](/calendarpit/ja/fixtures/)でローカルのクライアント認証情報と、完全一致するコールバック URI を登録してください。組み込みの `sample-app` / `local-sample-secret` は公開されているテスト用の値で、コールバックは `http://127.0.0.1:4175/callback` です。

オプションのソースサンプルでは、認可、イベント作成、FreeBusy、watch 通知、接続の取り消しを試せます。起動方法は[開発ガイド](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md)を参照してください。サンプルは配布サーバーとは別のアプリです。
