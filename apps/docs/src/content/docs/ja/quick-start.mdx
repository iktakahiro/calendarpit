## Calendarpit を起動する

Docker で起動します。

```sh
docker run --rm \
  -p 127.0.0.1:4173:4173 \
  -v calendarpit-data:/data \
  ghcr.io/iktakahiro/calendarpit:latest
```

Homebrew を使う場合は、インストールしてから起動します。

```sh
brew install iktakahiro/tap/calendarpit
calendarpit serve
```

どちらのコマンドでも、API、ローカル OAuth サーバー、管理画面が同じオリジンで起動します。

次のものは不要です。

- Google アカウント・Google Cloud プロジェクト
- 外部データベース
- `.env` ファイル
- プロバイダーの認証情報

Compose と単体ダウンロードは[インストール](/ja/installation/)で説明しています。

## 管理画面を開く

`http://127.0.0.1:4173` を開きます。API 経由の変更も自動で表示されます。各画面の使い方は[管理画面](/ja/admin-ui/)で説明しています。

組み込みの Fixture には次のデータが含まれます。

- テストユーザー `alex` と `sam`
- 3 つのカレンダー
- `2026-10-19` の planning イベント

### データの保存先

- **CLI**: 実行ディレクトリ内の `.calendarpit/calendarpit.sqlite`
- **Docker**: マウントしたボリューム

一時的なテストには、メモリ上のストレージを使います。

- **CLI**: `--database :memory:` を指定します。
- **Docker**: `-e CALENDARPIT_DATABASE=:memory:` を指定します。

[ストレージと再起動](/ja/storage/)も参照してください。

## アプリを接続する

1. [アプリを接続する](/ja/connect/)に従って、SDK と OAuth フローの接続先を Calendarpit に変更します。
2. [Fixture](/ja/fixtures/)で、ローカルのクライアント認証情報と完全一致するコールバック URI を登録します。

組み込みの `sample-app` / `local-sample-secret` は、公開されているテスト用の値です。コールバックは `http://127.0.0.1:4175/callback` です。

### リポジトリのサンプルアプリ（任意）

サンプルアプリでは、認可、イベント作成、FreeBusy、watch 通知、接続の取り消しを一通り試せます。サンプルは配布パッケージとは別のアプリです。起動方法は[開発ガイド](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md)を参照してください。

## コーディングエージェントにドキュメントを渡す

すべてのドキュメントページは、AI コーディングエージェント向けに Markdown でも公開しています。

- [llms.txt](https://calendarpit.dev/ja/llms.txt): 全ページの一覧と、各ページの Markdown 版へのリンク
- [llms-full.txt](https://calendarpit.dev/ja/llms-full.txt): 全ページを1ファイルにまとめたもの
- 1ページだけ渡すときは、ページのパスに `.md` を付けます。例: `https://calendarpit.dev/ja/quick-start.md`
