## Calendar API

Calendarpit は次のエンドポイントを提供します。アクセスのルールは次のとおりです。

- `/calendar/v3` の対応エンドポイントは、どれも Calendarpit のベアラートークンが必要です。スコープは[ローカル OAuth](/ja/oauth/)を参照してください。
- アクセスできるのは、認可したテストユーザーが所有するカレンダーだけです。
- `primary` は、そのユーザーのプライマリカレンダーを指します。
- 存在しないカレンダー ID や、所有していないカレンダー ID には `404`（`notFound`）を返します。
- 例外として、`freebusy.query` は `200` を返し、レスポンスの中でカレンダーごとに `notFound` エラーを示します。

表のパスは、すべて `/calendar/v3` からの相対パスです。

| メソッド                | パス                                                 | 動作                                                       |
| ----------------------- | ---------------------------------------------------- | ---------------------------------------------------------- |
| GET                     | `/users/me/calendarList`                             | 所有するカレンダーの一覧                                   |
| POST                    | `/users/me/calendarList`                             | 所有するカレンダーをリストに戻す                           |
| GET, PUT, PATCH, DELETE | `/users/me/calendarList/{calendarId}`                | リストのエントリを取得・置き換え・部分更新・リストから外す |
| POST                    | `/users/me/calendarList/watch`                       | カレンダーリストの変更を購読                               |
| GET                     | `/calendars/{calendarId}`                            | カレンダーのメタデータ（`id`、`summary`、`timeZone`）      |
| GET, POST               | `/calendars/{calendarId}/events`                     | イベントの一覧取得・作成                                   |
| GET, PUT, PATCH, DELETE | `/calendars/{calendarId}/events/{eventId}`           | イベントの取得・置き換え・部分更新・削除                   |
| GET                     | `/calendars/{calendarId}/events/{eventId}/instances` | 繰り返しイベントのインスタンスと例外                       |
| POST                    | `/freeBusy`                                          | 結合して期間内に切り詰めた busy 区間。最大50カレンダー     |
| POST                    | `/calendars/{calendarId}/events/watch`               | イベントの変更を購読                                       |
| POST                    | `/channels/stop`                                     | イベントまたはカレンダーリストの Watch チャネルを停止      |

`calendarList.list` のクエリパラメータは、後述の「一覧とページング」に記載しています。

未対応のメソッドには、明示的なエラーを返します。

## イベント

### 対応するフィールド

- `id`: `[a-zA-Z0-9@._-]{1,128}` に一致する値です。`primary` は使えません。ID が重複すると `409`（`duplicate`）を返します。
- `summary`、`description`、`location`
- `start`、`end`
- `transparency`: `opaque`、`transparent`
- `status`: `confirmed`、`tentative`、`cancelled`
- `visibility`: `default`、`public`、`private`、`confidential`
- `colorId`: `"1"`–`"11"`
- `attendees`、`attendeesOmitted`
- `guestsCanModify`、`guestsCanInviteOthers`、`guestsCanSeeOtherGuests`
- `reminders`、`recurrence`
- `conferenceData`: `conferenceDataVersion=1` が必要です。
- `hangoutLink`
- `extendedProperties.private`、`extendedProperties.shared`: 文字列マップです。

書き込み系のエンドポイントは、次のものも受け付けます。

- `sendUpdates`: `all`、`externalOnly`、`none`
- `conferenceDataVersion`: `0`、`1`

### サーバーが管理するフィールド

- レスポンスには `organizer`、`creator`、`iCalUID`、`sequence`、`created`、`updated`、引用符付きの `etag` が含まれます。
- `kind`、`etag`、`created`、`updated`、`calendarId`、`sequence` もリクエストで受け付けます。このため、取得したイベントをそのまま送り返せます。
- リクエストの `calendarId` は、`primary` ではなく解決後のカレンダー ID です。
- `organizer`、`creator`、`iCalUID`、`recurringEventId`、`originalStartTime` は読み取り専用です。更新時に値が変わっていなければ受け付けます。
- `events.insert` では、これらの読み取り専用フィールドを省略してください。Calendarpit が値を設定します。
- `sequence` は更新のたびに増えます。
- 保存済みイベントへの `GET`、`PUT`、`PATCH`、`DELETE` では `If-Match` を確認します。一致しない場合は `412`（`conditionNotMet`）を返します。

### PUT と PATCH

- **`PUT`** は書き込み可能フィールドを置き換えます。省略した任意フィールドはデフォルトに戻ります。
- **`PATCH`** は省略したフィールドを保持します。
  - `start` や `end` のオブジェクトを送ると、保存済みのオブジェクトをまるごと置き換えます。中のフィールドはマージしません。
  - `extendedProperties` のマップはキー単位でマージします。`null` でキーまたはマップ全体を削除します。
- 終日イベントの入力では `dateTime: null` と `timeZone: null` を受け付けます。

### 削除と削除済みレコード

`events.delete` は `204` を返し、`cancelled` の削除済みレコードを残します。すでに cancelled の場合は `410`（`deleted`）を返します。

| メソッド         | 削除済みレコード                                            |
| ---------------- | ----------------------------------------------------------- |
| `events.get`     | 返す                                                        |
| `freebusy.query` | 除外する                                                    |
| 一覧             | `showDeleted=true` か `updatedMin` を指定しない限り除外する |

`singleEvents=false` の場合、繰り返しの系列で cancelled になった例外は一覧に表示されたままです。

繰り返し、招待、リマインダー、ダミーの Meet リンク、時刻のルールは[イベント、繰り返し、時刻の扱い](/ja/recurrence/)を参照してください。

## カレンダーリスト

### エントリの形式

- カレンダーリストのエントリは `kind: "calendar#calendarListEntry"` です。
- `list` と `get` は同じ形式のエントリを返します。

所有するカレンダーは、最初は所有者のリストに次の値で載ります。

- `accessRole: "owner"`
- `selected: true`
- `colorId: "1"`（`backgroundColor: "#ac725e"`、`foregroundColor: "#1d1d1d"`）
- `defaultReminders: []`
- `primary`
- `conferenceProperties.allowedConferenceSolutionTypes: ["hangoutsMeet"]`

一部のフィールドは、条件によってだけ含まれます。

- `hidden` は `true` のときだけ含まれます。
- `summaryOverride` と `notificationSettings` は、空のとき省略されます。
- `deleted: true` は、リストから外したエントリと削除済みレコードにだけ付きます。
- `description` と `location` はレスポンスに含まれません。送ると `400`（`unsupportedFeature`）で拒否されます。

書き込みと同時更新の制御は次のとおりです。

- 読み取り専用フィールドは `kind`、`etag`、`id`、`summary`、`timeZone`、`accessRole`、`primary`、`deleted`、`conferenceProperties` です。
- 書き込み時は、読み取り専用フィールドの値が変わっていない場合だけ受け付けます。一致しない場合は `400`（`invalidParameter`）を返します。
- パスで `primary` を使う場合、`id` は `primary` も受け付けます。
- `etag` は、エントリの設定が変わると更新されます。カレンダーの `summary`、`timeZone`、`primary` フラグが変わったときも更新されます。
- `PATCH`、`PUT`、`DELETE` では `If-Match` を確認します。一致しない場合は `412`（`conditionNotMet`）を返します。

### 設定の書き込み（patch、update、insert）

ユーザーごとの書き込み可能な設定は、`summaryOverride`、`colorId`、`backgroundColor`、`foregroundColor`、`hidden`、`selected`、`defaultReminders`、`notificationSettings` です。

- SQLite 使用時は、再起動後も残ります。
- リセットや Fixture の読み込みで消えます。
- `summaryOverride` には、空白だけではない10,000文字以内の文字列が必要です。`""` は `400` を返します。

省略したフィールドの扱いは、書き込みの種類で異なります。

- **`PATCH`** は、省略した書き込み可能フィールドを保持します。`null` で `summaryOverride`、`defaultReminders`、`notificationSettings` を消去します。
- **`PUT` と `insert`**（`200`）は、書き込み可能フィールドを置き換えます。
  - 省略した `summaryOverride`、`defaultReminders`、`notificationSettings` は消去されます。
  - `hidden` と `selected` は `false` に戻ります。一度も書き込んでいないエントリは `selected: true` のままです。
  - 色を指定しない場合、`colorId` は `"1"` に戻ります。
- **内容が変わらない書き込み**は `200` を返します。`etag` は変わらず、カレンダーリストのページトークンも無効にならず、Watch チャネルにも通知しません。

### 色

- `colorId` はパレット ID `"1"`–`"24"` を受け付けます。前景色は `"#1d1d1d"` です。
- 未知の ID や、`"constructor"` のような継承プロパティ名は `400` を返します。

**`colorRgbFormat=true` を指定した場合**:

- `insert`、`patch`、`update` のどれでも、`backgroundColor` と `foregroundColor`（`#rrggbb`）の両方が必要です。ない場合は `400` を返します。
- 送った `colorId` は無視され、最も近いパレット色が設定されます。

**`colorRgbFormat=true` を指定しない場合**:

- RGB フィールドには、表示中の色と同じ値しか送れません。
- `PATCH` で現在の `colorId` と RGB を同じ値で送ると、カスタムの色を保持します。
- `PUT` と `insert` でカスタムの RGB を保持するには、`colorRgbFormat=true` を送る必要があります。
- 別の `colorId` を指定すると、カスタムの RGB は消えます。

### リマインダーと通知

- `defaultReminders` は `{method: "email" | "popup", minutes: 0–40320}` の項目を5件まで受け付けます。
- `notificationSettings.notifications` は `{method: "email", type}` の項目を5件まで受け付けます。
  - `type` は `eventCreation`、`eventChange`、`eventCancellation`、`eventResponse`、`agenda` のいずれかです。
  - `type` は重複できません。重複すると `400` を返します。
- どちらの設定でもメールは送信されません。
- `PATCH {"notificationSettings": {}}` は既存の通知を保持します。
- `[]`、`null`、または `notifications` なしの `PUT` は通知を消去します。

<Callout type="info">

次の2つの動作は Google のリファレンスに合わせたもので、実際の Google では確認していません。

- `colorRgbFormat=true` で `colorId` を無視する動作
- `PATCH {"notificationSettings": {}}` で通知を保持する動作

</Callout>

### 削除と insert

**`calendarList.delete`**（`204`）は、プライマリ以外のカレンダーを呼び出し元のリストから外すだけです。

- プライマリカレンダーには `403`（`cannotDeletePrimaryCalendar`）を返します。
- すでに外している場合は `404` を返します。
- 外したカレンダーとそのイベントには、`calendars.get`、`events.*`、`freebusy.query`、`events.watch` で引き続きアクセスできます。
- そのカレンダーに対する `calendarList.get`、`patch`、`update` は `404` を返します。

**`calendarList.insert`** は、リストから外した所有カレンダーを戻します（`200`）。

- `id` が必要です。ない場合は `400` を返します。
- カレンダーを新しく作ることはありません。
- すでにリストにあるカレンダー（非表示のものと `primary` を含む）は `409`（`duplicate`）を返します。非表示を解除するには `patch` を使ってください。

**管理 API による影響**:

- プライマリカレンダーを削除すると、リストに残っている最初のカレンダーがプライマリになります。
- すべてリストから外れている場合は、所有する最初のカレンダーを保存済みの設定のままリストに戻します。
- `primary: true` を設定した場合も、リストから外したカレンダーはリストに戻ります。

### watch

`calendarList.watch` は、ループバックの許可リスト、配信ログ、`channels.stop` エンドポイントを `events.watch` と共有します。[watch 通知](/ja/watch/)を参照してください。

- 開始時に `sync` を送ります。
- その後、リストへの書き込みで保存済みの設定が変わったときに `exists` を送ります。
- 管理 API でユーザーのカレンダーを作成・更新・削除したときも `exists` を送ります。
- イベントへの書き込みでは送りません。
- その他のクエリパラメータ（`syncToken` を含む）は `400`（`unsupportedFeature`）を返します。
- `params`（`params.ttl` など）も `400`（`unsupportedFeature`）を返します。

## 一覧とページング

### `calendarList.list`

`calendarList.list` は次のパラメータを受け付けます。

- `maxResults`、`pageToken`
- `minAccessRole`: `freeBusyReader`、`reader`、`writer`、`owner`。所有するカレンダーはすべて `owner` ロールなので、有効な値であればどれでも一致します。
- `showHidden`: デフォルトは `false` です。このとき `list` は `hidden: true` のエントリを返しません。`get` では取得できます。
- `showDeleted`: 下記を参照してください。

レスポンスにはコレクションの `etag` が含まれます。`nextSyncToken` はありません。

`showDeleted=true` を指定すると、次の `deleted: true` のエントリも返します。

- **`calendarList.delete` でリストから外したカレンダー**: `hidden: true` でも、保存済みの設定を保持します。
- **管理 API で削除したカレンダーの削除済みレコード**: リストのデフォルト設定を使います。削除したカレンダーがプライマリだった場合は `primary: true` を保持します。

### `events.list`

`events.list` は次のパラメータを受け付けます。

- `timeMin`、`timeMax`、`updatedMin`: オフセット付きの RFC 3339 タイムスタンプが必要です。
- `maxResults`: 1–2500、デフォルト 250
- `orderBy`: `startTime`、`updated`。`orderBy=startTime` には `singleEvents=true` が必要です。
- `pageToken`、`singleEvents`、`timeZone`、`showDeleted`、`syncToken`、`iCalUID`
- `privateExtendedProperty=name=value`、`sharedExtendedProperty=name=value`: 繰り返し指定できるフィルタです。すべて一致する必要があります。

範囲の判定と並び順は次のとおりです。

- 範囲の判定には `start < timeMax` と `end > timeMin` を使います。
- `orderBy` を指定しない一覧は、イベント ID 順に並びます。

<Callout type="warn">

カレンダーに終了日のない繰り返しの系列がある場合は、次のとおりです。

- `singleEvents=true` または `timeMin` を指定した `events.list` には `timeMax` が必要です。
- その系列への `events.instances` には、常に `timeMax` が必要です。

`timeMax` がない場合は `400`（`unsupportedFeature`）を返します。

</Callout>

### ページトークン

- イベント一覧のページングでは、最初のページの時点でスナップショットを固定します。ページ取得の合間に書き込みがあっても、項目は抜けません。
- イベントのページトークンは、クエリとユーザーに結び付いています。
- イベントのページトークンは1時間で期限が切れます。再起動・リセット・Fixture の読み込みでも消えます。
- カレンダーリストのページトークンは、データやカレンダーリストへの書き込みがあると無効になります。保存はされません。
- 期限切れや無効なトークンは `410`（`invalidPageToken`）を返します。

`syncToken` と `nextSyncToken` は[差分同期](/ja/sync/)を参照してください。

## 明示的に除外している機能

次の機能には対応していません。

- ACL・共有カレンダー・委任
- カレンダーグループ
- カラーパレット（`colors.get`）
- ユーザー設定
- カレンダーリストの同期トークン
- ACL と設定の watch
- フリーテキスト検索（`q`）
- `eventTypes`
- 添付ファイル
- 実際のメール送信
- 実際の Google Meet の作成
- 完全な OIDC

### リクエストの検証

- 未知のボディフィールドは `400`（`unsupportedFeature`）を返します。
- 未知のクエリパラメータ（`fields` を含む）は、`/calendar/v3` のすべてのエンドポイントで `400`（`unsupportedFeature`）を返します。
- 例外として、`channels.stop` はクエリ文字列を無視します。
- トランスポート用のパラメータ（`alt=json`、`prettyPrint`、`quotaUser`、`key`）は受け付けます。
- API キーは、OAuth のベアラートークンの代わりにはなりません。
- Calendarpit が Google にリクエストを中継したり、Google と同期したりすることはありません。

カレンダーの管理とデータのリセットは[テスト制御 API](/ja/test-control/)を参照してください。クライアントの接続先を Calendarpit にする方法は[アプリを接続する](/ja/connect/)を参照してください。
