Calendarpit は API、OAuth、管理画面を同じオリジンで提供します。

以下は配布パッケージを使う起動方法です。ソースのクローンやビルドは不要です。必要な環境と対応プラットフォームは[インストール](/ja/installation/)を参照してください。

## Calendarpit の起動方法

### Docker と Compose

```sh
docker run --rm \
  -p 127.0.0.1:4173:4173 \
  -v calendarpit-data:/data \
  ghcr.io/iktakahiro/calendarpit:latest
```

コンテナのデフォルト設定は次のとおりです。

- 非 root ユーザーで動作します。
- `CALENDARPIT_HOST=0.0.0.0` と `CALENDARPIT_PORT=4173` が設定されています。
- SQLite は `/data/calendarpit.sqlite` に保存されます。

ホスト側に公開するポートはループバックに限定しています。環境変数はイメージ名の前に `-e` で指定します。CLI フラグはイメージ名の後に渡します。

```sh
docker run --rm -p 127.0.0.1:4173:4173 \
  ghcr.io/iktakahiro/calendarpit:latest serve --database :memory:
```

関連ページ:

- [インストール](/ja/installation/): Compose のサービス定義、ヘルスチェック、ホストとコンテナの接続先
- [Fixture](/ja/fixtures/): 起動時の設定ファイルをマウントする方法
- [開発ガイド](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md): ソースからの開発手順

### インストール済みの CLI

Homebrew でインストールするか、単体実行ファイルを `PATH` に配置します。そのうえで、プロジェクトのディレクトリで起動します。導入方法は[インストール](/ja/installation/)を参照してください。

```sh
calendarpit serve --port 4173
calendarpit serve --port 0 --database :memory:
```

これらは起動コマンドの例です。

- 同じデータベースファイルを使うサーバーは1つだけ起動してください。
- ポート `0` を指定すると、OS が空きポートを割り当てます。
- 実際の URL は起動時の出力で確認できます。

```text
Calendarpit data: :memory:

Calendarpit v<version>
Data   :memory:
Admin  http://127.0.0.1:38425/
API    http://127.0.0.1:38425/calendar/v3
Health http://127.0.0.1:38425/__calendarpit/health
```

配布実行ファイルには、サーバー、管理画面のアセット（`favicon.svg` を含む）、Bun ランタイムが含まれています。Node.js も Bun も別途インストールする必要はありません。サーバーは Ctrl+C で停止します。

## コマンドラインオプションと環境変数

CLI の構文は `calendarpit [serve] [options]` です。`serve` サブコマンドは省略できます。

次の場合、CLI は `stderr` にエラーを出力し、終了コード `1` で終了します。

- 未知のコマンド
- 未知のフラグ
- 無効なオプション値

コマンドラインフラグは環境変数より優先されます。

| CLI オプション      | 環境変数               | デフォルト                        | 説明                                                                                                                                                |
| ------------------- | ---------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--host <host>`     | `CALENDARPIT_HOST`     | `127.0.0.1`                       | バインドするアドレスです。ループバック以外（`0.0.0.0`、`::`）は明示的な指定が必要です。                                                             |
| `-p`, `--port <n>`  | `CALENDARPIT_PORT`     | `4173`                            | リッスンするポート番号（`0`〜`65535`）です。`0` を指定すると OS が空きポートを割り当てます。                                                        |
| `--database <path>` | `CALENDARPIT_DATABASE` | `.calendarpit/calendarpit.sqlite` | SQLite データベースファイルのパス、または使い捨てのインメモリセッション用の `:memory:` です。[ストレージと再起動](/ja/storage/)を参照してください。 |
| `--config <path>`   | `CALENDARPIT_CONFIG`   | 組み込み Fixture                  | 起動時 Fixture の JSON ファイルのパスです。[Fixture](/ja/fixtures/)を参照してください。                                                             |
| `-h`, `--help`      | —                      | —                                 | ヘルプを表示して終了します。                                                                                                                        |
| `-v`, `--version`   | —                      | —                                 | バージョンを表示して終了します。                                                                                                                    |

オプションの補足:

- **`--port 0`**: 割り当てられたポート番号は起動時の出力に表示されます。
- **ポート `4175`**: リファレンスのサンプルアプリも併用する場合は避けてください。
- **`--config`**: ファイルが存在し、有効な JSON である必要があります。新規データベースまたは `:memory:` セッションの初期データとして使われます。

<Callout type="warn">

既存の SQLite ファイルを開くとき、`--config` はエラーを出さずに無視されます。

</Callout>

### その他の環境変数

| 環境変数                  | デフォルト       | 説明                                                                                                       |
| ------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------- |
| `CALENDARPIT_WATCH_HOSTS` | ループバックのみ | `events.watch` と `calendarList.watch` の Webhook 送信先として追加で許可するホスト名（カンマ区切り）です。 |

`CALENDARPIT_WATCH_HOSTS` の補足:

- 例: Docker 内で実行する場合の `host.docker.internal`
- 環境変数でのみ設定できます。対応する CLI フラグはありません。
- 詳しくは[watch 通知](/ja/watch/)を参照してください。

### ループバックへのバインドと作業ディレクトリ

**デフォルトはループバックです。** `--host` または `CALENDARPIT_HOST` を指定しない限り、Calendarpit は `127.0.0.1` にバインドします。

<Callout type="warn">

管理画面と[テスト制御 API](/ja/test-control/) には認証がありません。`0.0.0.0` にバインドすると、同じネットワーク上の他のマシンからアクセスできるようになります。

</Callout>

**相対パス。** パスの解決方法は起動方法によって異なります。

- **Homebrew・単体実行ファイル**: `--database` と `--config`（および対応する環境変数）の相対パスは、起動したディレクトリを基準に解決されます。プロジェクトのディレクトリから起動するか、絶対パスを指定してください。
- **Docker**: コンテナ内のパスを使います。参照する前に、ホスト上のファイルをマウントしてください。

起動時のよくあるエラーは[トラブルシューティング](/ja/troubleshooting/)を参照してください。

## 管理画面

管理画面は、API と同じオリジンのルートで提供されます。デフォルトの URL は `http://127.0.0.1:4173/` です。ワークスペース、リクエスト履歴、Webhook の配信を確認し、テストデータを編集できます。詳しくは[管理画面](/ja/admin-ui/)を参照してください。
