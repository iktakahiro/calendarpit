Calendarpit は API、OAuth、管理画面を同じオリジンで提供します。npm、Docker Compose、Homebrew、単体実行ファイルの導入方法と公開状況は[インストール](/calendarpit/ja/installation/)を参照してください。以下のソース用コマンドは、[開発ガイド](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md)に従ってクローンと依存関係のインストールを済ませた場合に使用できます。

## Calendarpit の起動方法

### 開発サーバー

デフォルトのアドレス（`http://127.0.0.1:4173`）でローカルサーバーを起動するときは、`bun run dev` を使います。

```sh
bun run dev
CALENDARPIT_DATABASE=:memory: bun run dev
```

`bun run dev` は常に `127.0.0.1:4173` にバインドし、ポートが使用中であればエラーで終了します。コマンドラインフラグや `CALENDARPIT_HOST`、`CALENDARPIT_PORT` は `bun run dev` には適用されません。引き継がれる環境変数は `CALENDARPIT_DATABASE`、`CALENDARPIT_CONFIG`、`CALENDARPIT_WATCH_HOSTS` だけです。

### ビルド済みサーバー

ローカルスクリプトや CI で CLI フラグ、任意のポート、OS による空きポートの自動割り当て（`--port 0`）を使うときは、`bun run build` と `bun run start` を使います。`build` の前に `start` を実行すると、`Calendarpit: Build the application first with "bun run build".` を出力して終了します。

CLI フラグは `--` の後に渡すか、Bun で CLI エントリポイントを直接実行してください。

```sh
bun run build
bun run start -- --port 0 --database :memory:
bun apps/calendarpit/bin/calendarpit.ts serve --port 4173
```

ビルド済みサーバーが起動すると、ストレージモードと、割り当てられたポートを含む各 URL が出力されます。

```text
Calendarpit data: :memory:

Calendarpit v0.9.0
Data   :memory:
Admin  http://127.0.0.1:38425/
API    http://127.0.0.1:38425/calendar/v3
Health http://127.0.0.1:38425/__calendarpit/health
```

### 単体実行ファイル

`bun run build:binary` を実行すると、`apps/calendarpit/dist/bin/calendarpit`（Windows では `.exe` 付き）に単体実行ファイルがコンパイルされます。このファイルは、同じマシン上の別のディレクトリやテストランナーにコピーして使えます。

```sh
bun run build:binary
./apps/calendarpit/dist/bin/calendarpit serve --port 4173 --database :memory:
```

単体実行ファイルには、サーバー本体、クライアント用の JavaScript、CSS、ファビコン、Bun ランタイムが埋め込まれています。実行時に `node_modules` や別のアセットディレクトリは必要ありません。デフォルトでは実行したホスト向けにコンパイルします。リリースビルドでは macOS arm64/x64、Linux glibc arm64/x64、Windows x64 も対象にしています。

### Docker

公開イメージと Compose の使用方法は[インストール](/calendarpit/ja/installation/)を参照してください。ソースからビルドする場合:

```sh
docker build -t calendarpit:local .
docker run --rm -p 127.0.0.1:4173:4173 -v calendarpit-data:/data calendarpit:local
```

コンテナは非 root ユーザーで動作し、`CALENDARPIT_HOST=0.0.0.0` と `CALENDARPIT_PORT=4173` を明示的に設定しています。引数を渡してもこの環境変数は保持されます。SQLite は `/data/calendarpit.sqlite` に保存します。

## コマンドラインオプションと環境変数

CLI の構文は `calendarpit [serve] [options]` です。`serve` サブコマンドは省略できます。未知のコマンド、未知のフラグ、無効なオプション値を渡すと、`stderr` にエラーを出力し、終了コード `1` で終了します。

コマンドラインフラグは環境変数より優先されます。

| CLI オプション      | 環境変数               | デフォルト                        | 説明                                                                                                                                                                                                                                                                                                                |
| ------------------- | ---------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--host <host>`     | `CALENDARPIT_HOST`     | `127.0.0.1`                       | バインドするアドレスです。ループバック以外のアドレス（`0.0.0.0`、`::`）は明示的に指定する必要があります。                                                                                                                                                                                                           |
| `-p`, `--port <n>`  | `CALENDARPIT_PORT`     | `4173`                            | リッスンするポート番号（`0`〜`65535`）です。`0` を指定すると OS が空きポートを割り当て、起動時の出力にそのポート番号が表示されます。`bun run sample:dev` も併用する場合は `4175` を避けてください。                                                                                                                 |
| `--database <path>` | `CALENDARPIT_DATABASE` | `.calendarpit/calendarpit.sqlite` | SQLite データベースファイルのパスです。使い捨てのインメモリセッションには `:memory:` を指定します。詳しくは[ストレージと再起動](/calendarpit/ja/storage/)を参照してください。                                                                                                                                       |
| `--config <path>`   | `CALENDARPIT_CONFIG`   | 組み込みフィクスチャ              | 起動時フィクスチャの JSON ファイルのパスです。ファイルが存在し、有効な JSON である必要があります。新規データベースまたは `:memory:` セッションの初期データとして使われます。既存の SQLite ファイルを開くときは、エラーを出さずに無視されます。詳しくは[フィクスチャ](/calendarpit/ja/fixtures/)を参照してください。 |
| `-h`, `--help`      | —                      | —                                 | ヘルプを表示して終了します。ビルド前でも動作します。                                                                                                                                                                                                                                                                |
| `-v`, `--version`   | —                      | —                                 | `0.9.0` を表示して終了します。ビルド前でも動作します。                                                                                                                                                                                                                                                              |

### その他の環境変数

| 環境変数                  | デフォルト       | 説明                                                                                                                                                                                                                                                                                                |
| ------------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CALENDARPIT_WATCH_HOSTS` | ループバックのみ | `events.watch` と `calendarList.watch` の Webhook 送信先として追加で許可するホスト名を、カンマ区切りで指定します（例: Docker 内で実行する場合の `host.docker.internal`）。環境変数でのみ設定でき、対応する CLI フラグはありません。詳しくは[watch 通知](/calendarpit/ja/watch/)を参照してください。 |

### ループバックへのバインドと作業ディレクトリ

- **デフォルトはループバック**: `--host` または `CALENDARPIT_HOST` を指定しない限り、Calendarpit は `127.0.0.1` にバインドします。管理画面と[テスト制御 API](/calendarpit/ja/test-control/) には認証がありません。`0.0.0.0` にバインドすると、同じネットワーク上の他のマシンからアクセスできるようになります。
- **ワークスペーススクリプトでの相対パス**: `bun run dev` と `bun run start` は、`apps/calendarpit` を作業ディレクトリとして実行されます。そのため、`--database`、`CALENDARPIT_DATABASE`、`--config`、`CALENDARPIT_CONFIG` に指定した相対パスは `apps/calendarpit` を基準に解決されます（デフォルトの SQLite パスは `apps/calendarpit/.calendarpit/calendarpit.sqlite` になります）。CLI エントリポイントを直接実行した場合は、現在のディレクトリを基準に解決されます。リポジトリのルートからワークスペースコマンドを実行するときは、`"$PWD/fixtures/default.json"` のような絶対パスを使ってください。起動時のよくあるエラーは[トラブルシューティング](/calendarpit/ja/troubleshooting/)を参照してください。

## 管理画面

管理画面は、API と同じオリジンのルート（デフォルトは `http://127.0.0.1:4173/`）で提供されます。2 秒ごとに `GET /__calendarpit/state` とリクエスト履歴をポーリングするため、お使いのアプリが行った変更は自動で画面に反映されます。左側のナビゲーションでは、表示するテストユーザーとカレンダー（`?user=<id>&calendar=<id>`）を切り替えたり、ストレージが `SQLite` か `In-memory` かを確認したりできます。

管理画面は Google Fonts（`fonts.googleapis.com` と `fonts.gstatic.com`）から Roboto Mono フォントを読み込みます。オフラインのときはシステムフォントを使います。Calendar API と OAuth の処理は Google に接続せず、インターネット接続も必要ありません。

| ルート         | セクション      | 用途                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`            | **Schedule**    | 保存されているイベントを日表示または週表示で確認します（デフォルトの日付は `2026-10-19`）。イベントの作成、編集、削除（件名、終日イベントの切り替え、開始・終了日時、busy/free 状態、場所、説明、拡張プロパティ JSON）ができます。繰り返しの系列は最初の 1 回分だけが表示され、展開されません。エディタでイベントを保存すると、フォームに表示されている項目でイベントが置き換えられます。Calendar API で設定した参加者、リマインダー、色などの項目は削除され、繰り返しイベントは `recurrence` を失います。これらのイベントを編集するときは Calendar API を使ってください。 |
| `/users`       | **Users**       | テストユーザーの一覧表示、作成、編集、削除を行います。ユーザーを削除すると、そのユーザーのカレンダーとイベントも削除され、OAuth 認可も取り消されます（関連する watch チャネルも停止します）。                                                                                                                                                                                                                                                                                                                                                                              |
| `/calendars`   | **Calendars**   | 選択中のテストユーザーのカレンダーの一覧表示、作成、編集、削除を行います。IANA タイムゾーン（デフォルトは `Asia/Tokyo`）の設定と、プライマリカレンダーの選択もできます。                                                                                                                                                                                                                                                                                                                                                                                                   |
| `/connections` | **Connections** | テストユーザーと OAuth クライアントごとに、有効な OAuth 認可と取り消し済みの OAuth 認可を確認します。有効な認可は取り消せます（関連する watch チャネルも停止します）。詳しくは[ローカル OAuth](/calendarpit/ja/oauth/)を参照してください。                                                                                                                                                                                                                                                                                                                                 |
| `/watch`       | **Watch**       | 有効な watch チャネルと Webhook の配信ログを読み取り専用で確認します。詳しくは[watch 通知](/calendarpit/ja/watch/)を参照してください。                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `/history`     | **API history** | 直近 200 件の Calendar API と OAuth のリクエスト履歴（認証情報はマスク済み）を確認し、テキストでの絞り込み、HTTP `>= 400` のエラーのみの表示、履歴の消去を行います。                                                                                                                                                                                                                                                                                                                                                                                                       |
| `/settings`    | **Settings**    | テーマの切り替え（**Appearance**）、ストレージパスの確認、フィクスチャ JSON ファイルの読み込み、リセット基準（起動時の状態）へのワークスペースのリセット、現在の状態 JSON の確認（**Test data**）、登録済みの OAuth クライアントとリダイレクト URI の確認（**OAuth clients**）を行います。                                                                                                                                                                                                                                                                                 |
