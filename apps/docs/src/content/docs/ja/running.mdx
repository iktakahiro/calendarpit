Calendarpit は API、OAuth、管理画面を同じオリジンで提供します。必要な環境、対応プラットフォーム、0.9.0 の公開状況は[インストール](/ja/installation/)を参照してください。以下は配布パッケージを使う起動方法です。ソースのクローンやビルドは不要です。

## Calendarpit の起動方法

### インストール済みの CLI

Homebrew でインストールするか、単体実行ファイルを `PATH` に配置してから、プロジェクトのディレクトリで起動します。導入方法は[インストール](/ja/installation/)を参照してください。

```sh
calendarpit serve --port 4173
calendarpit serve --port 0 --database :memory:
```

これらは起動コマンドの例です。同じデータベースファイルを使うサーバーは 1 つだけ起動してください。ポート `0` を指定すると OS が空きポートを割り当てます。実際の URL は起動時の出力で確認できます。

```text
Calendarpit data: :memory:

Calendarpit v0.9.0
Data   :memory:
Admin  http://127.0.0.1:38425/
API    http://127.0.0.1:38425/calendar/v3
Health http://127.0.0.1:38425/__calendarpit/health
```

配布実行ファイルには、サーバー、管理画面のアセット（`favicon.svg` を含む）、Bun ランタイムが含まれています。Node.js も Bun も別途インストールする必要はありません。サーバーは Ctrl+C で停止します。

### Docker と Compose

```sh
docker run --rm \
  -p 127.0.0.1:4173:4173 \
  -v calendarpit-data:/data \
  ghcr.io/iktakahiro/calendarpit:0.9.0
```

コンテナは非 root ユーザーで動作し、`CALENDARPIT_HOST=0.0.0.0` と `CALENDARPIT_PORT=4173` が設定されています。SQLite は `/data/calendarpit.sqlite` に保存されます。ホスト側に公開するポートはループバックに限定しています。環境変数はイメージ名の前に `-e` で指定し、CLI フラグはイメージ名の後に渡します。

```sh
docker run --rm -p 127.0.0.1:4173:4173 \
  ghcr.io/iktakahiro/calendarpit:0.9.0 serve --database :memory:
```

Compose のサービス定義、ヘルスチェック、ホストとコンテナの接続先は[インストール](/ja/installation/)を参照してください。起動時の設定ファイルをマウントする方法は[Fixture](/ja/fixtures/)で説明しています。ソースからの開発手順は[開発ガイド](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md)にあります。

## コマンドラインオプションと環境変数

CLI の構文は `calendarpit [serve] [options]` です。`serve` サブコマンドは省略できます。未知のコマンドやフラグ、無効なオプション値を渡すと、`stderr` にエラーを出力して終了コード `1` で終了します。

コマンドラインフラグは環境変数より優先されます。

| CLI オプション      | 環境変数               | デフォルト                        | 説明                                                                                                                                                                                                                                                                                            |
| ------------------- | ---------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--host <host>`     | `CALENDARPIT_HOST`     | `127.0.0.1`                       | バインドするアドレスです。ループバック以外のアドレス（`0.0.0.0`、`::`）は明示的に指定する必要があります。                                                                                                                                                                                       |
| `-p`, `--port <n>`  | `CALENDARPIT_PORT`     | `4173`                            | リッスンするポート番号（`0`〜`65535`）です。`0` を指定すると OS が空きポートを割り当て、起動時の出力にそのポート番号が表示されます。リファレンスのサンプルアプリも併用する場合は `4175` を避けてください。                                                                                      |
| `--database <path>` | `CALENDARPIT_DATABASE` | `.calendarpit/calendarpit.sqlite` | SQLite データベースファイルのパスです。使い捨てのインメモリセッションには `:memory:` を指定します。詳しくは[ストレージと再起動](/ja/storage/)を参照してください。                                                                                                                               |
| `--config <path>`   | `CALENDARPIT_CONFIG`   | 組み込み Fixture                  | 起動時 Fixture の JSON ファイルのパスです。ファイルが存在し、有効な JSON である必要があります。新規データベースまたは `:memory:` セッションの初期データとして使われます。既存の SQLite ファイルを開くときは、エラーを出さずに無視されます。詳しくは[Fixture](/ja/fixtures/)を参照してください。 |
| `-h`, `--help`      | —                      | —                                 | ヘルプを表示して終了します。                                                                                                                                                                                                                                                                    |
| `-v`, `--version`   | —                      | —                                 | `0.9.0` を表示して終了します。                                                                                                                                                                                                                                                                  |

### その他の環境変数

| 環境変数                  | デフォルト       | 説明                                                                                                                                                                                                                                                                                    |
| ------------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CALENDARPIT_WATCH_HOSTS` | ループバックのみ | `events.watch` と `calendarList.watch` の Webhook 送信先として追加で許可するホスト名を、カンマ区切りで指定します（例: Docker 内で実行する場合の `host.docker.internal`）。環境変数でのみ設定でき、対応する CLI フラグはありません。詳しくは[watch 通知](/ja/watch/)を参照してください。 |

### ループバックへのバインドと作業ディレクトリ

- **デフォルトはループバック**: `--host` または `CALENDARPIT_HOST` を指定しない限り、Calendarpit は `127.0.0.1` にバインドします。管理画面と[テスト制御 API](/ja/test-control/) には認証がありません。`0.0.0.0` にバインドすると、同じネットワーク上の他のマシンからアクセスできるようになります。
- **相対パス**: Homebrew や単体実行ファイルでは、`--database` と `--config`（および対応する環境変数）の相対パスは起動したディレクトリを基準に解決されます。プロジェクトのディレクトリから起動するか、絶対パスを指定してください。Docker ではコンテナ内のパスを使い、ホスト上のファイルをマウントします。起動時のよくあるエラーは[トラブルシューティング](/ja/troubleshooting/)を参照してください。

## 管理画面

管理画面は、API と同じオリジンのルート（デフォルトは `http://127.0.0.1:4173/`）で提供されます。2 秒ごとに `GET /__calendarpit/state` とリクエスト履歴をポーリングするため、アプリが行った変更は自動で画面に反映されます。左側のナビゲーションでは、表示するテストユーザーとカレンダー（`?user=<id>&calendar=<id>`）を切り替えたり、ストレージが `SQLite` か `In-memory` かを確認したりできます。

管理画面は Google Fonts（`fonts.googleapis.com` と `fonts.gstatic.com`）から Roboto Mono フォントを読み込みます。オフラインのときはシステムフォントを使います。Calendar API と OAuth の処理は Google に接続せず、インターネット接続も必要ありません。

| ルート         | セクション      | 用途                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`            | **Schedule**    | 保存されているイベントを日表示または週表示で確認します（デフォルトの日付は `2026-10-19`）。イベントの作成、編集、削除（件名、終日イベントの切り替え、開始・終了日時、busy/free 状態、場所、説明、拡張プロパティ JSON）ができます。繰り返しの系列は最初の 1 回分だけが表示され、展開されません。エディタでイベントを保存すると、フォームに表示されている項目でイベントが置き換えられます。Calendar API で設定した参加者、色などの項目は削除され、繰り返しイベントは `recurrence` を失います。カスタムリマインダーはデフォルト（`reminders: { useDefault: true }`）に戻ります。これらのイベントを編集するときは Calendar API を使ってください。 |
| `/users`       | **Users**       | テストユーザーの一覧表示、作成、編集、削除を行います。ユーザーを削除すると、そのユーザーのカレンダーとイベントも削除され、OAuth 認可も取り消されます（関連する watch チャネルも停止します）。                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `/calendars`   | **Calendars**   | 選択中のテストユーザーについて、カレンダーの一覧表示、作成、編集、削除を行います。IANA タイムゾーン（デフォルトは `Asia/Tokyo`）の設定と、プライマリカレンダーの選択もできます。                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `/connections` | **Connections** | テストユーザーと OAuth クライアントごとに、有効または取り消し済みの OAuth 認可を確認します。有効な認可は取り消せます（関連する watch チャネルも停止します）。詳しくは[ローカル OAuth](/ja/oauth/)を参照してください。                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `/watch`       | **Watch**       | 有効な watch チャネルと Webhook の配信ログを読み取り専用で確認します。詳しくは[watch 通知](/ja/watch/)を参照してください。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `/history`     | **API history** | 直近 200 件の Calendar API と OAuth のリクエスト履歴（認証情報はマスク済み）を確認できます。テキストでの絞り込み、HTTP `>= 400` のエラーのみの表示、履歴の消去も可能です。                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `/settings`    | **Settings**    | テーマの切り替え（**Appearance**）、ストレージパスの確認、Fixture JSON ファイルの読み込み、リセット基準（起動時の状態）へのワークスペースのリセット、現在の状態 JSON の確認（**Test data**）、登録済みの OAuth クライアントとリダイレクト URI の確認（**OAuth clients**）を行います。                                                                                                                                                                                                                                                                                                                                                         |
