Calendarpit にはローカルの OAuth 2.0 認可サーバーが含まれており、Google Cloud プロジェクトや実際の Google アカウントなしでアプリをテストできます。認可時には、ローカルの同意画面のドロップダウンからテストユーザーを選択します。パスワードは入力しません。

フローを開始する前に、アプリの OAuth クライアントと Google Calendar SDK の接続先を `http://127.0.0.1:4173` に向けてください。エンドポイントの設定方法は、[アプリを接続する](/calendarpit/ja/connect/)を参照してください。

## エンドポイント

| メソッド | パス                                          | 用途                                                                                                                                                                                 |
| -------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET`    | `/oauth/authorize`                            | 認可リクエストを検証し、ローカルの HTML 同意画面を表示します                                                                                                                         |
| `POST`   | `/oauth/authorize`                            | 同意の選択結果（`approve` または `deny`）を送信し、`redirect_uri` へ `302` でリダイレクトします（同一オリジンのリクエストのみ。クロスサイトリクエストは `403 forbidden` を返します） |
| `POST`   | `/oauth/token`                                | 認可コードまたはリフレッシュトークンをアクセストークンと交換します                                                                                                                   |
| `POST`   | `/oauth/revoke`                               | アクセストークンまたはリフレッシュトークンと、その接続（grant）を失効させます                                                                                                        |
| `GET`    | `/userinfo`                                   | 認可されたテストユーザーのプロフィールクレームを返します                                                                                                                             |
| `POST`   | `/__calendarpit/connections/{grantId}/revoke` | 管理 API から接続を失効させます（`204`。管理 API のリクエスト規則が適用されます。詳細は[テスト制御 API](/calendarpit/ja/test-control/)を参照してください）                           |

ルーティングされるのは上記のパスのみです。`/oauth2/...` 配下の Google エンドポイント（`/oauth2/v4/token` や `/oauth2/v3/userinfo` など）や、`/oauth/*` に対する誤った HTTP メソッドは、ステータス `501` と `{"error":"unsupportedFeature","error_description":"Unsupported API endpoint or method."}` を返します。

## 認可コードフロー

1. **フィクスチャに OAuth クライアントを登録します。** 起動時フィクスチャの `clients` 配列に、`id`、`secret`、`redirectUris` を持つエントリを追加します。各リダイレクト URI は、フラグメントや userinfo を含まない `http:` または `https:` の絶対 URL である必要があります。起動時フィクスチャがシードされるのは、新規データベースまたは `:memory:` セッションの場合のみです。既存のデータベースファイルを使用している場合は、`POST /__calendarpit/fixtures` でフィクスチャを読み込む（次のリセットまでワークスペースのデータを置き換えます）か、新しいデータベースで起動してください。詳細は[フィクスチャ](/calendarpit/ja/fixtures/)および[ストレージと再起動](/calendarpit/ja/storage/)を参照してください。デフォルトのフィクスチャ（`--config` も `CALENDARPIT_CONFIG` も指定しない場合に使用されます）には、ID が `sample-app`、シークレットが `local-sample-secret`、リダイレクト URI が `http://127.0.0.1:4175/callback` のクライアントが含まれています。
2. **ブラウザを `GET /oauth/authorize` へ遷移させます。** `http://127.0.0.1:4173/oauth/authorize` に、以下のクエリパラメータを URL エンコードして付与します。
   - `client_id`（必須）: 登録済みのクライアント ID（未登録の ID は `400 invalid_client` を返します）。
   - `redirect_uri`（必須）: コールバック URL。クライアントの `redirectUris` のいずれかと文字列として完全一致する必要があります（ループバックポートのワイルドカードや末尾スラッシュの正規化は行われません。不一致の場合は `400 invalid_request` を返します）。
   - `response_type`（必須）: `code` を指定します。
   - `scope`（必須）: 対応しているスコープをスペース区切りで指定します（[スコープ](#スコープ)を参照）。
   - `state`（任意）: ユーザーのブラウザセッションに紐づくランダムな値です。指定した場合、リダイレクト時にそのまま返されます。
   - `access_type`（任意）: `online` または `offline`。リフレッシュトークンを受け取るには `access_type=offline` を指定します。
   - `code_challenge` および `code_challenge_method`（任意）: PKCE パラメータです。使用する場合は、`code_challenge_method` に `S256` を、`code_challenge` に 43 文字の base64url ダイジェストを指定する必要があります。
   - `prompt`（任意）: `consent`、`select_account`、`consent select_account`、`select_account consent` のいずれかを受け付けます。同意画面は常に表示されます。
   - `include_granted_scopes`（任意）: 指定する場合は `false` でなければなりません。
3. **同意画面で承認または拒否します。** 同意画面には、ワークスペース内のすべてのテストユーザー（`Name · email`）と、要求されたスコープ文字列の一覧が表示されます。テストユーザーを選択し、**Approve** または **Deny** をクリックします。
   - **Approve** をクリックすると、新しい接続（grant）が作成され、`<redirect_uri>?state=<state>&code=<code>` へリダイレクト（`302`）されます。
   - **Deny** をクリックすると、`<redirect_uri>?state=<state>&error=access_denied` へリダイレクト（`302`）されます。
4. **コールバックハンドラで `state` を検証します。** クエリパラメータの `state` と、リダイレクト前に保存しておいたセッションの値を比較します。`error=access_denied` が含まれている場合は処理を中断し、`/oauth/token` は呼び出さないでください。
5. **`POST /oauth/token` で認可コードを交換します。** `application/x-www-form-urlencoded` 形式のボディに、`grant_type=authorization_code`、`code`、`redirect_uri`（ステップ 2 と同一のもの）、クライアント認証情報、および `code_verifier`（PKCE を使用した場合）を含めて送信します。エンドポイントは以下の JSON を返します。
   ```json
   {
     "access_token": "...",
     "token_type": "Bearer",
     "expires_in": 3600,
     "scope": "https://www.googleapis.com/auth/calendar email profile",
     "refresh_token": "..."
   }
   ```
   `refresh_token` は、認可リクエストに `access_type=offline` が含まれている場合のみ返されます。
6. **アクセストークンを使って API を呼び出します。** `/calendar/v3/...` や `GET /userinfo` へのリクエストに `Authorization: Bearer <access_token>` ヘッダーを付与します。詳細は[SDK の使用例](/calendarpit/ja/sdks/)を参照してください。

## HTTP リクエスト例

`PIT_CLIENT_ID`、`PIT_CLIENT_SECRET`、`PIT_REDIRECT_URI`、`PIT_CODE` にクライアントの値とコールバックで受け取った認可コードを、`PIT_REFRESH_TOKEN` と `CALENDARPIT_ACCESS_TOKEN` に交換時に取得した `refresh_token` と `access_token` を設定してください（これらはこの例でのみ使用するシェル変数です）。PKCE を使用した場合は、コード交換時に `--data-urlencode "code_verifier=$PIT_VERIFIER"` も渡してください。Profile のリクエストには、`openid`、`email`、`profile`、`userinfo.*` のいずれかのスコープが必要です。

## クライアント認証・有効期限・失効

### クライアント認証

`POST /oauth/token` のすべての呼び出し（`authorization_code` および `refresh_token`）では、PKCE を使用している場合でもクライアント認証が必須です。シークレットを持たないパブリッククライアントには対応していません。認証情報は以下の 2 通りの方法で指定できます。

- **フォームフィールド（`client_secret_post`）:** URL エンコードされたボディに `client_id` と `client_secret` を含めます。
- **HTTP Basic（`client_secret_basic`）:** `Authorization: Basic <base64(urlencode(client_id):urlencode(client_secret))>` ヘッダーを送信します。両方が送信された場合は、`Authorization` ヘッダーが優先されます。

`POST /oauth/token` は、`Content-Type` ヘッダーの値にかかわらず、常にボディを `application/x-www-form-urlencoded` としてパースします。JSON ボディは読み取られません。JSON を送信すると、リクエストは `400 invalid_client` で失敗します（認証情報を HTTP Basic で渡している場合は `400 unsupported_grant_type` で失敗します）。

### 有効期限と永続化

| 対象                 | 有効期限                                                                   | 1 回限り | SQLite 使用時の再起動後の永続化 |
| -------------------- | -------------------------------------------------------------------------- | -------- | ------------------------------- |
| 保留中の同意 nonce   | 5 分（保留数の上限は 1,000 件。超過時は `429 rateLimitExceeded`）          | はい     | いいえ                          |
| 認可コード           | 60 秒（`client_id` と `redirect_uri` に紐づく）                            | はい     | いいえ                          |
| アクセストークン     | 1 時間（`expires_in: 3600`）                                               | いいえ   | はい（元の有効期限を維持）      |
| リフレッシュトークン | 失効、テストユーザーの削除、リセット、またはフィクスチャ読み込みまで無期限 | いいえ   | はい                            |
| 接続（grant）        | 失効、テストユーザーの削除、リセット、またはフィクスチャ読み込みまで有効   | いいえ   | はい                            |

`:memory:` モードでは、プロセスが終了するとすべての OAuth の状態が失われます。詳細は[ストレージと再起動](/calendarpit/ja/storage/)を参照してください。

### リフレッシュと失効

- **リフレッシュ:** `grant_type=refresh_token` は新しい `access_token`（`expires_in: 3600`）を発行します。`refresh_token` の返却やローテーションは行われず、既存のリフレッシュトークンが引き続き有効です。リフレッシュリクエストに `scope` を含める場合は、認可時のスペース区切りのスコープ文字列と完全一致する必要があります。一致しない場合は `400 invalid_scope` で失敗します。
- **失効（`POST /oauth/revoke`）:** `token` フォームフィールド（または `?token=` クエリパラメータ）にアクセストークンまたはリフレッシュトークンを渡します。クライアント認証は不要です。どちらのトークンを失効させても接続（grant）全体が失効し、その接続に紐づくすべてのアクセストークン、リフレッシュトークン、認可コードが削除され、watch チャネルが停止します。未知のトークンを渡した場合は空のボディで `200` を返し、`token` が未指定、空、または空白のみの場合は `400 invalidParameter` を返します。
- **その他の無効化トリガー:** 管理画面からの接続の失効（`POST /__calendarpit/connections/{grantId}/revoke`）やテストユーザーの削除（`DELETE /__calendarpit/users/{id}`）を行うと、対象の接続またはユーザーのトークンが無効化され、watch チャネルが停止します。`POST /__calendarpit/reset` または `POST /__calendarpit/fixtures` を呼び出すと、すべての接続、トークン、認可コード、保留中の同意が削除され、すべての watch チャネルが停止します。詳細は[テスト制御 API](/calendarpit/ja/test-control/)を参照してください。

## スコープ

すべての `GET /oauth/authorize` リクエストには、対応しているスコープを少なくとも 1 つ含める必要があります。それ以外のスコープを要求すると `400 invalid_scope` を返します。

| スコープ                                                         | 許可される操作                                                                                                                                                                     |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `https://www.googleapis.com/auth/calendar`                       | 対応しているすべての Calendar API の読み書き（`calendarList.*`, `calendars.get`, `events.*`, `channels.stop`, `freebusy.query`）                                                   |
| `https://www.googleapis.com/auth/calendar.readonly`              | `calendarList.list`, `calendarList.get`, `calendarList.watch`, `calendars.get`, `events.list`, `events.get`, `events.instances`, `events.watch`, `channels.stop`, `freebusy.query` |
| `https://www.googleapis.com/auth/calendar.events`                | `events.list`, `events.get`, `events.instances`, `events.insert`, `events.update`, `events.patch`, `events.delete`, `events.watch`, `channels.stop`, `freebusy.query`              |
| `https://www.googleapis.com/auth/calendar.events.readonly`       | `events.list`, `events.get`, `events.instances`, `events.watch`, `channels.stop`, `freebusy.query`                                                                                 |
| `https://www.googleapis.com/auth/calendar.calendarlist`          | `calendarList.list`, `calendarList.get`, `calendarList.insert`, `calendarList.patch`, `calendarList.update`, `calendarList.delete`, `calendarList.watch`, `channels.stop`          |
| `https://www.googleapis.com/auth/calendar.calendarlist.readonly` | `calendarList.list`, `calendarList.get`, `calendarList.watch`, `channels.stop`                                                                                                     |
| `https://www.googleapis.com/auth/calendar.calendars.readonly`    | `calendars.get`                                                                                                                                                                    |
| `https://www.googleapis.com/auth/calendar.freebusy`              | `freebusy.query`                                                                                                                                                                   |
| `https://www.googleapis.com/auth/calendar.events.freebusy`       | `freebusy.query`                                                                                                                                                                   |
| `openid`                                                         | `GET /userinfo` — `{ sub, id }` を返します（どちらもテストユーザー ID が設定されます）                                                                                             |
| `email`, `https://www.googleapis.com/auth/userinfo.email`        | `GET /userinfo` — `{ sub, id }` に加えて `email`、`verified_email: true`、`email_verified: true` を返します                                                                        |
| `profile`, `https://www.googleapis.com/auth/userinfo.profile`    | `GET /userinfo` — `{ sub, id }` に加えて `name` を返します                                                                                                                         |

アクセストークンが未指定、期限切れ、または失効している場合は、`WWW-Authenticate: Bearer` ヘッダーとともに `401`（`authError`）を返します。有効なトークンであっても、そのエンドポイントに必要なスコープが含まれていない場合は `403`（`insufficientPermissions`）を返します。また、`channels.stop` にはチャネルを開いた接続（grant）のトークンが必要であり、別の接続のトークンでは `404`（`notFound`）を返します。`/oauth/*` エンドポイントとは異なり、`GET /userinfo` および Calendar API エンドポイントは Google API のエラーエンベロープ形式でエラーを返します。詳細は[トラブルシューティング](/calendarpit/ja/troubleshooting/)を参照してください。

`openid` スコープは、`{ sub, id }` を返す `GET /userinfo` へのアクセスのみを許可します。Calendarpit は `/oauth/token` から `id_token` を返さず、`/.well-known/openid-configuration` や JWKS の配信も行いません。また、`/userinfo` のレスポンスに `picture`、`given_name`、`family_name`、`locale` は含まれません。

## 未対応の OAuth 機能

`GET /oauth/authorize` でのバリデーションエラーは、`redirect_uri` へリダイレクトせず、ブラウザに直接ステータス `400` の JSON レスポンス（`{"error": "<reason>", "error_description": "<message>"}`）を返します。

- **未登録の `client_id`** は `400 invalid_client`（"Unknown client."）を返します。
- **未登録の `redirect_uri`**（クライアントの `redirectUris` のいずれとも文字列として完全一致しないもの）は `400 invalid_request`（"Unregistered redirect URI."）を返します。
- **未知の認可パラメータ**（`nonce`、`login_hint`、`hd`、`request`、`request_uri`、`enable_granular_consent` など）は `400 unsupported_feature` を返します。
- **非対話型の同意**（`prompt=none`、またはステップ 2 に記載された 4 つ以外の `prompt` 値）は `400 unsupported_feature` を返します。
- **増分認可（Incremental authorization）**（`include_granted_scopes=true`）は `400 unsupported_feature` を返します。
- **その他のレスポンスタイプ**（`response_type=code` 以外）は `400 unsupported_response_type` を返します。
- **PKCE の `plain` メソッド**は `400 invalid_request` を返します。
- **一覧にないスコープ**（`calendar.events.owned`、`calendar.app.created`、`calendar.settings.readonly`、`calendar.acls`、または書き込みスコープの `calendar.calendars` など）は `400 invalid_scope` を返します。
- **`POST /oauth/token` でのその他の grant type** は（クライアント認証の成功後に）`400 unsupported_grant_type` を返します。
- **API キー（`key=` クエリパラメータ）** は API リクエストのシステムパラメータとして受け付けられますが、Bearer トークン認証の代わりにはなりません。

未対応の Google 機能の一覧については、[対応範囲と制限](/calendarpit/ja/scope/)を参照してください。
