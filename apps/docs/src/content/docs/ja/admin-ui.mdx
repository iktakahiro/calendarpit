管理画面は、ローカルのワークスペースをブラウザで確認するための画面です。開発中はアプリの横に開いておくと便利です。アプリが書き込んだデータや送ったリクエストを確認し、次のテストに向けてデータを変更できます。

管理画面は API と同じオリジンのルートで提供されます。デフォルトの URL は `http://127.0.0.1:4173/` です。サインインは不要です。

## 画面の構成

左側のナビゲーションで、すべての画面に共通する表示対象を決めます。

- **Live**: 管理画面は 2 秒ごとに `GET /__calendarpit/state` とリクエスト履歴をポーリングします。アプリが行った変更は再読み込みなしで反映されます。サーバーが応答しなくなると **Disconnected** に変わります。
- **Test user** と **Calendars**: 各画面に表示するユーザーとカレンダーを選択します。選択内容は URL（`?user=<id>&calendar=<id>`）に保持されるため、ブックマークや共有ができます。
- **セクション**: 先頭は **Schedule** です。**Activity** にはアプリが行ったことを確認する API history、Watch、Connections が、**Workspace** にはテストデータを扱う Users、Calendars、Settings がまとまっています。数字は、履歴の件数、有効な watch チャネル、有効な接続を表します。
- **ストレージ**: 下部に `SQLite` か `In-memory` かと、サーバーのアドレスが表示されます。詳しくは[ストレージと再起動](/ja/storage/)を参照してください。

各セクションのヘッダーにある **Refresh** ボタンを押すと、ワークスペースをすぐに再読み込みします。

| ルート         | 画面            | 用途                                                                  |
| -------------- | --------------- | --------------------------------------------------------------------- |
| `/`            | **Schedule**    | イベントの表示、作成、編集、削除                                      |
| `/history`     | **API history** | 直近の Calendar API と OAuth の通信の確認と消去                       |
| `/watch`       | **Watch**       | watch チャネルと Webhook 配信の確認（読み取り専用）                   |
| `/connections` | **Connections** | OAuth 認可の確認と取り消し                                            |
| `/users`       | **Users**       | テストユーザーの作成、編集、削除                                      |
| `/calendars`   | **Calendars**   | 選択中のユーザーのカレンダーの作成と設定                              |
| `/settings`    | **Settings**    | テーマ、言語、ストレージ、Fixture、リセット、状態、OAuth クライアント |

<Callout type="warn">

管理画面には認証がありません。Calendarpit はデフォルトで `127.0.0.1` にバインドします。別のアドレスにバインドすると、管理画面がほかのマシンから見えるようになります。詳しくは[ループバックへのバインド](/ja/running/#ループバックへのバインドと作業ディレクトリ)を参照してください。

</Callout>

## アプリが書き込んだイベントを確認する

**Schedule** には、選択中のカレンダーに入っているイベントが表示されます。カレンダー自体の作成は [Calendars](#テストユーザーとカレンダーを管理する) で行います。

デフォルトの日付は、組み込み Fixture の planning イベントがある `2026-10-19` です。

- **Day** は 24 時間のトラックとイベント一覧を、**Week** は日曜から土曜までの時間グリッドを表示します。
- 矢印、日付ピッカー、**Today** で日付を移動します。日付と表示形式は URL（`?date=2026-10-19&view=week`）に保持されます。
- 時刻はカレンダーのタイムゾーンで表示されます。終了時刻はその時刻を含みません。busy のイベントは塗りつぶしで、free（transparent）のイベントは斜線または枠線で表示され、空き時間をふさぎません。
- 繰り返しの系列は最初の 1 回分だけが表示され、展開されません。保存された例外は、それぞれの日付に表示されます。

  caption='日表示。現在時刻つきの 24 時間トラックと、イベント一覧。'

### イベントを作成・編集する

イベントを選択するとエディタで開きます。**New event** を選ぶと新規作成です。週表示では、空いている枠を選ぶとその時刻でイベントを作成できます。

エディタで扱う項目は、件名、終日イベントの切り替え、開始と終了、空き状況（busy または free）、場所、説明、拡張プロパティ（JSON）です。

<AdminScreen
  view='event-editor'
  caption='イベントエディタはスケジュールの横に開きます。開いているイベントは URL（?event=planning）に保持されます。'
/>

<Callout type="warn">

エディタでイベントを保存すると、フォームに表示されている項目でイベントが置き換えられます。

- Calendar API で設定した参加者、色などの項目は削除されます。
- 繰り返しイベントは `recurrence` を失います。
- カスタムリマインダーはデフォルト（`reminders: { useDefault: true }`）に戻ります。

これらのイベントを編集するときは Calendar API を使ってください。詳しくは[スコープ](/ja/scope/)を参照してください。

</Callout>

## テストユーザーとカレンダーを管理する

テストユーザーはローカルの ID で、パスワードはありません。アプリは[ローカルの同意画面](/ja/oauth/)で、いずれかのテストユーザーとしてサインインします。

**Users** には、すべてのテストユーザーがメールアドレスとカレンダー数つきで表示されます。ユーザーを選択すると、名前とメールアドレスを編集できます。

- ユーザーを削除すると、そのユーザーのカレンダーとイベントも削除されます。
- ユーザーを削除すると OAuth 接続も取り消され、関連する watch チャネルも停止します。

**Calendars** では、イベントではなく、選択中のユーザーが持つカレンダーそのものを管理します。カレンダーの作成、名前の変更、削除を行い、各カレンダーの IANA タイムゾーン（デフォルトは `Asia/Tokyo`）とプライマリにするカレンダーを設定できます。

- プライマリカレンダーは、Calendar API でカレンダー ID `primary` が指すカレンダーです。
- カレンダーのタイムゾーンを変更すると、`timeZone` パラメータを明示せずに発行された同期トークンは無効になります。詳しくは[差分同期](/ja/sync/)を参照してください。

  view='calendars'
  caption='Calendars。選択中のユーザーのカレンダー名、タイムゾーン、プライマリ設定を編集します。'

## アプリのリクエストを追跡する

**API history** には、直近 200 件の Calendar API と OAuth のやり取りが新しい順に記録されます。SDK が何を送り、Calendarpit が何を返したかを正確に確認できます。

- 各行には、ステータス、メソッド、パス、領域（`calendar` や `oauth` など）、時刻が表示されます。
- 行を選択すると、リクエストとレスポンスのヘッダーとボディを確認できます。**Copy** で JSON としてコピーできます。
- `Authorization` ヘッダー、トークン、クライアントシークレット、認可コードなどの認証情報は `[REDACTED]` にマスクされます。
- メソッド、パス、ステータスで絞り込めます。**Errors** を選ぶと、ステータスが `400` 以上のレスポンスだけを表示します。
- **Clear history** で一覧を消去します。

<AdminScreen
  view='history'
  caption='存在しないイベントの取得を展開したところ。レスポンスは Google API のエラー形式です。'
/>

よくあるエラーと対処は[トラブルシューティング](/ja/troubleshooting/)で説明しています。

## watch 通知を確認する

**Watch** は、プッシュ通知を読み取り専用で確認する画面です。すべてのカレンダーのチャネルが対象です。

- **Watch channels** には、有効なチャネルが、対象のカレンダー（またはカレンダーリスト）、コールバックアドレス、有効期限とともに表示されます。
- **Delivery log** には、直近 200 件の配信が表示されます。チャネルとメッセージ番号、リソースの状態（`sync` または `exists`）、試行回数、時刻、結果を確認できます。結果は `queued`、`delivered`、`failed`、`cancelled` のいずれかで、エンドポイントが最後に返した HTTP ステータスも表示されます。

<AdminScreen
  view='watch'
  caption='エンドポイントが 503 を返した配信は、3 回試行したあと failed になります。'
/>

自動テストでは、この画面を見る代わりに `POST /__calendarpit/deliveries/drain` で配信の完了を待ちます。詳しくは[watch 通知](/ja/watch/)を参照してください。

## 再接続をテストする

**Connections** には、OAuth 認可がテストユーザーと OAuth クライアントごとに、スコープと認可日時つきで表示されます。

有効な認可で **Revoke** を選ぶと、アプリの復帰処理をテストできます。認可を取り消すとトークンが無効になり、関連する watch チャネルも停止します。

- 古いアクセストークンを使った次の Calendar API リクエストは `401 authError` で失敗します。
- 古いリフレッシュトークンでの更新は `invalid_grant` で失敗します。

アプリはユーザーにもう一度 [OAuth フロー](/ja/oauth/)を通ってもらう必要があります。

## テストデータを準備する

**Settings** には 3 つのタブがあります。

### Appearance

- **Theme**: **Light**、**Dark**、**System** から選びます。**System** はデバイスのカラースキームに従い、デバイスが設定を返さない場合は **Dark** になります。
- **Language**: **English**、**日本語**、**System** から選びます。**System** はブラウザの優先言語に従い、日本語でも英語でもない場合は English になります。

どちらの設定も最初は **System** で、選ぶまでは何も保存されません。選んだ内容はブラウザの Cookie に 1 年間保存されるため、次にページを開いたときも選んだテーマと言語で表示されます。

言語の設定が変えるのは画面の文言だけです。ナビゲーション、見出し、ボタン、フォームのラベル、メッセージ、日付が対象です。パス、HTTP メソッドとステータス、JSON、スコープ、リソースの状態、ID といったプロトコルのデータは、Calendarpit が送受信するとおりに表示されます。[ローカルの同意画面](/ja/oauth/)は常に英語です。

### Test data

- **Storage** には、ストレージの種類と SQLite のパス（または `:memory:`）が表示されます。
- **Fixtures & reset** では [Fixture](/ja/fixtures/) を読み込めます。JSON を貼り付けるか **Open JSON file…** を選び、**Load fixture** を選びます。読み込むと、ユーザー、カレンダー、イベント、OAuth クライアントが置き換えられ、接続、リクエスト履歴、watch チャネルが消去されます。リセット基準は変わりません。
- **Reset workspace** は起動時の Fixture を復元し、接続、リクエスト履歴、watch チャネルを消去します。
- **Current state** には、ワークスペースの状態が認証情報を除いた JSON で表示されます。

どちらの操作も、実行前に確認が表示されます。スクリプトからは[テスト制御 API](/ja/test-control/) で同じ操作ができます。

<AdminScreen
  view='test-data'
  caption='Settings → Test data。ストレージの種類、Fixture の読み込み、ワークスペースのリセット。'
/>

### OAuth clients

Fixture を再読み込みせずに、OAuth クライアントを追加・編集・削除できます。コールバック URL の追加やシークレットの差し替えに使います。ユーザー、イベント、接続はそのまま残ります。詳しくは[アプリを接続する](/ja/connect/)を参照してください。

<AdminScreen
  view='oauth-clients'
  caption='Settings → OAuth clients には、各クライアントとリダイレクト URI が表示されます。'
/>

管理画面は Google Fonts（`fonts.googleapis.com` と `fonts.gstatic.com`）から Roboto Mono フォントを読み込みます。オフラインのときはシステムフォントを使います。Calendar API と OAuth の処理は Google に接続せず、インターネット接続も必要ありません。
