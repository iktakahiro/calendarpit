管理画面は、ローカルの Calendarpit ワークスペースをブラウザで操作・確認する画面です。アプリを動かしながら開いておくと、アプリが Calendar API で Calendarpit に作成・更新したイベント、送信した各リクエストや Webhook 配信を確認し、次のテストに向けてデータを編集できます。

管理画面は API と同じオリジンのルート（デフォルトは `http://127.0.0.1:4173/`）で提供され、サインインは不要です。

## 画面の構成

左側のナビゲーションで、すべての画面に共通する表示対象を切り替えます。

- **Live**: 管理画面は `GET /__calendarpit/changes` を購読し、サーバーが変更を保存するとすぐに状態とリクエスト履歴を読み直します。アプリが Calendar API で行った変更は、ページを再読み込みしなくてもすぐに反映されます。フォールバックとして30秒ごとのポーリングも続けます。サーバーが応答しなくなると **Disconnected** に変わり、復旧すると自動で再接続します。
- **Test user** と **Calendars**: 各画面に表示するテストユーザーとカレンダーを選択します。選択状態は URL（`?user=<id>&calendar=<id>`）に保持されるため、そのままブックマークや共有ができます。
- **セクション**: 先頭は **Schedule** です。**Activity** にはアプリの動作を確認する **API history**、**Watch**、**Connections** が、**Workspace** にはテストデータを管理する **Users**、**Calendars**、**Settings** が並んでいます。バッジの数字は、記録された履歴の件数、有効な watch チャネル数、有効な OAuth 接続数を表します。
- **ストレージ**: 下部にストレージモード（`SQLite` または `In-memory`）とサーバーのアドレスが表示されます。詳しくは[ストレージと再起動](/ja/storage/)を参照してください。

各画面のヘッダーにある **Refresh** ボタンを押すと、ワークスペースの状態を即座に再読み込みします。

| ルート         | 画面            | 用途                                                                                                                        |
| -------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `/`            | **Schedule**    | 選択中のカレンダーのイベントを表示、作成、編集、削除                                                                        |
| `/history`     | **API history** | 直近の Calendar API と OAuth のリクエスト・レスポンスの確認と消去                                                           |
| `/watch`       | **Watch**       | 有効な watch チャネルと Webhook 配信の確認（読み取り専用）                                                                  |
| `/connections` | **Connections** | OAuth 認可（接続）の確認と取り消し                                                                                          |
| `/users`       | **Users**       | テストユーザーの作成、編集、削除                                                                                            |
| `/calendars`   | **Calendars**   | 選択中のユーザーのカレンダーの作成と設定                                                                                    |
| `/settings`    | **Settings**    | テーマ、言語、Calendar API のレート制限、ストレージモード、Fixture 読み込み、リセット、状態の JSON 表示、OAuth クライアント |

<Callout type="warn">

管理画面には認証がありません。Calendarpit はデフォルトで `127.0.0.1` にバインドします。別のアドレスにバインドすると、管理画面がほかのマシンからもアクセス可能になります。詳しくは[ループバックへのバインド](/ja/running/#ループバックへのバインドと作業ディレクトリ)を参照してください。

</Callout>

## コマンドパレットとキーボードショートカット

macOS では <kbd>⌘</kbd> <kbd>K</kbd>、それ以外では <kbd>Ctrl</kbd> <kbd>K</kbd> を押すか、セクションのヘッダーにある **Commands** を選ぶと、コマンドパレットが開きます。文字を入力して絞り込み、矢印キーで移動し、<kbd>Enter</kbd> でコマンドを実行します。<kbd>?</kbd> でもパレットが開き、各コマンドのショートカットを確認できます。

- 各セクションへの移動、イベントの作成、テーマの変更ができます。
- パレットは表示言語にかかわらず英語です。セクション名は `ユーザー` のような日本語の名前でも検索できます。
- テストユーザーの名前やメールアドレス、カレンダー名を入力すると、そのユーザーやカレンダーに切り替えられます。**Switch user…** と **Switch calendar…** では一覧から選べます。
- **Go to date…** には `2026-10-21`、`today`、`tomorrow`、`yesterday`、または表示中の日付からの差分（`+3`、`-1`、`+1w` など）を入力できます。

**Go to date…** のようなパレット内のページでは、空の入力欄で <kbd>Backspace</kbd> を押すと、すべてのコマンドの一覧に戻ります。

| ショートカット                                           | 操作                                         |
| -------------------------------------------------------- | -------------------------------------------- |
| <kbd>⌘</kbd> <kbd>K</kbd> / <kbd>Ctrl</kbd> <kbd>K</kbd> | コマンドパレットを開く、閉じる               |
| <kbd>?</kbd>                                             | コマンドパレットを開く                       |
| <kbd>⌘</kbd> <kbd>,</kbd> / <kbd>Ctrl</kbd> <kbd>,</kbd> | **Settings** を開く                          |
| <kbd>C</kbd>                                             | 選択中のカレンダーにイベントを作成する       |
| <kbd>T</kbd>                                             | 今日を表示する                               |
| <kbd>P</kbd> / <kbd>N</kbd>                              | 前日・翌日を表示する（週表示では前週・翌週） |
| <kbd>D</kbd> / <kbd>W</kbd>                              | 日表示・週表示に切り替える                   |
| <kbd>G</kbd>                                             | 日付を指定して移動する                       |

<kbd>T</kbd>、<kbd>P</kbd>、<kbd>N</kbd>、<kbd>D</kbd>、<kbd>W</kbd>、
<kbd>G</kbd> は **Schedule** で使えます。それ以外はすべての画面で使えます。

入力欄に入力している間や、イベントエディタやダイアログにフォーカスがある間は、1文字のショートカットは反応しません。イベントのタイトルを入力してもショートカットが動くことはありません。

## アプリが書き込んだイベントを確認する

**Schedule** には、アプリが Calendar API で Calendarpit に作成・更新したイベントを含め、選択中のカレンダーのイベントが表示されます。カレンダー自体の作成や設定は [Calendars](#テストユーザーとカレンダーを管理する) で行います。

デフォルトの日付は、組み込み Fixture の planning イベントがある `2026-10-19` です。

- **Day** は24時間のタイムラインとその日のイベント一覧を、**Week** は日曜から土曜までの7日間の時間グリッドを表示します。
- 矢印ボタン、日付ピッカー、**Today** で日付を移動します。選択した日付と表示形式は URL（`?date=2026-10-19&view=week`）に保持されます。
- 時刻は選択中のカレンダーのタイムゾーンで表示されます。終了時刻はその時刻を含みません。busy のイベントは塗りつぶしで表示され、free（transparent）のイベントは斜線または枠線で表示されて `freeBusy` クエリで空き時間をふさぎません。
- 繰り返しイベントの系列は最初の1回分だけが表示され、スケジュール画面上では展開されません。保存された例外インスタンスは、それぞれの日付に表示されます。

### イベントを作成・編集する

既存のイベントを選択するとエディタで開きます。**New event** を押すと新規作成になります。週表示では、空いている時間枠をクリックしてその時刻のイベントを作成できます。

エディタでは、件名、終日イベントの切り替え、開始・終了日時、空き状況（busy または free）、場所、説明、拡張プロパティ（JSON）を編集できます。

<AdminScreen
  view='event-editor'
  caption='イベントエディタはスケジュールの横に開きます。開いているイベントは URL（?event=planning）に保持されます。'
/>

<Callout type="warn">

エディタでイベントを保存すると、フォームにある項目だけでイベントが上書きされます。

- Calendar API で設定した参加者（`attendees`）や色などの項目は消えます。
- 繰り返しイベントは `recurrence` ルールを失い、単発のイベントになります。
- カスタムリマインダーはデフォルト（`reminders: { useDefault: true }`）に戻ります。

これらの項目を持つイベントを編集するときは Calendar API を使ってください。詳しくは[対応範囲と制限](/ja/scope/)を参照してください。

</Callout>

## テストユーザーとカレンダーを管理する

テストユーザーはパスワードを持たないローカルのアカウントです。アプリが OAuth フローを開始したら、[ローカルの同意画面](/ja/oauth/)でテストユーザーを1人選んでサインインします。

**Users** には、すべてのテストユーザーがメールアドレスとカレンダー数つきで表示されます。ユーザーを選択すると、表示名とメールアドレスを編集できます。

- ユーザーを削除すると、そのユーザーのカレンダーとイベントもすべて削除されます。
- ユーザーを削除すると、そのユーザーの OAuth 接続（認可）も取り消され、発行済みのトークンが失効して watch チャネルも停止します。

**Calendars** では、イベントではなく、選択中のユーザーが所有するカレンダー自体を管理します。カレンダーの作成、名前の変更、削除のほか、各カレンダーの IANA タイムゾーン（デフォルトは `Asia/Tokyo`）とプライマリカレンダーを設定します。

- プライマリカレンダーは、Calendar API でカレンダー ID に `primary` を指定したときに参照されるカレンダーです。
- カレンダーのタイムゾーンを変更すると、`timeZone` パラメータを指定せずに発行された差分同期トークン（`syncToken`）は無効になります。詳しくは[差分同期](/ja/sync/)を参照してください。

## アプリのリクエストを追跡する

**API history** には、アプリが Calendarpit に送信した直近200件の Calendar API と OAuth のリクエストが新しい順に記録されます。SDK や HTTP クライアントが実際に送った内容と、Calendarpit が返したレスポンスを確認できます。

- 各行には、HTTP ステータス、メソッド、パス、領域（`calendar` や `oauth` など）、時刻が表示されます。
- 行を選択すると、リクエストとレスポンスのヘッダーおよびボディが表示されます。**Copy** を押すとペイロードを JSON としてコピーできます。
- `Authorization` ヘッダー、アクセストークン・リフレッシュトークン、クライアントシークレット、認可コードなどの認証情報は `[REDACTED]` にマスクされます。
- メソッド、パス、ステータスで絞り込めます。**Errors** を選ぶと、ステータスコード `400` 以上のエラーレスポンスだけを表示します。
- **Clear history** を押すと記録をすべて消去します。

<AdminScreen
  view='history'
  caption='存在しないイベントへの GET リクエストを展開した画面。リクエストヘッダーと、Google API 形式の 404 エラーレスポンスを確認できます。'
/>

よくあるエラーレスポンスと対処方法は[トラブルシューティング](/ja/troubleshooting/)を参照してください。

## watch 通知を確認する

**Watch** は、すべてのカレンダーのプッシュ通知を読み取り専用で確認する画面です。

- **Watch channels** には、有効な watch チャネルが、監視対象のカレンダー（または `CalendarList`）、アプリのコールバック URL、有効期限とともに表示されます。
- **Delivery log** には、直近200件の Webhook 配信が記録されます。チャネル ID とメッセージ番号、リソースの状態（`sync` または `exists`）、試行回数、時刻、配信結果（`queued`、`delivered`、`failed`、`cancelled`）、およびアプリのエンドポイントが最後に返した HTTP ステータスを確認できます。

<AdminScreen
  view='watch'
  caption='Watch 画面。有効なチャネルの一覧と、エンドポイントが HTTP 503 を返して3回の試行後に failed となった Webhook 配信。'
/>

自動テストでは、この画面を目視する代わりに `POST /__calendarpit/deliveries/drain` を呼び出して配信完了を待機します。詳しくは[watch 通知](/ja/watch/)を参照してください。

## 再接続をテストする

**Connections** の各「接続」は、テストユーザーが同意画面でアプリを承認したときに作られる OAuth の認可（grant）を表します。画面には、どのテストユーザーがどの OAuth クライアントにどのスコープを許可したかと、認可した日時が表示されます。アクセストークンとリフレッシュトークンは、この認可に対して発行されます。

有効な接続で **Revoke** を押すと、認可が取り消されたときのアプリの再接続処理をテストできます。取り消すと、その認可で発行されたアクセストークン、リフレッシュトークン、認可コードが削除され、その認可で作られた watch チャネルも停止します。

- 古いアクセストークンを使った以降の Calendar API リクエストは `401 authError` で失敗します。
- 古いリフレッシュトークンを使った `POST /oauth/token` でのトークン更新は `400 invalid_grant` で失敗します。

どちらのトークンも使えなくなるため、アプリはユーザーをもう一度 [OAuth フロー](/ja/oauth/)に誘導して認可を取り直す必要があります。

## テストデータを準備する

**Settings** には4つのタブがあります。

### Appearance

- **Theme**: **Light**、**Dark**、**System** から選びます。**System** はデバイスのカラースキームに従い、デバイスが設定を返さない場合は **Dark** になります。
- **Language**: **English**、**日本語**、**System** から選びます。**System** はブラウザの優先言語に従い、日本語でも英語でもない場合は English になります。

どちらの設定も最初は **System** で、選ぶまでは何も保存されません。選んだ内容はブラウザの Cookie に1年間保存されるため、次にページを開いたときも選んだテーマと言語で表示されます。

言語の設定が変えるのは画面の文言だけです。ナビゲーション、見出し、ボタン、フォームのラベル、メッセージ、日付が対象です。パス、HTTP メソッドとステータス、JSON、スコープ、リソースの状態、ID といったプロトコルのデータは、Calendarpit が送受信するとおりに表示されます。[ローカルの同意画面](/ja/oauth/)は常に英語です。

### Developer

**Calendar API rate limits** では、`/calendar/v3` のリクエストをどう制限するかを設定します。

- **オフ**（`off`）はリクエストを制限しません。これがデフォルトです。
- **本番相当**（`production`）は、Google の公開クォータにほぼ準じた制限を使います（完全一致ではありません）。カレンダーごとの書き込み制限は Google が公開していないため、Calendarpit の推定値です。
- **エラー確認用**（`error-test`）は極端に低い制限を使い、`403` と `429` のクォータエラーがすぐ発生します。リトライやバックオフの処理を確認するときに使います。

選択したモードはワークスペースに保存されます。SQLite の場合は再起動後も維持されます。リセットや Fixture の読み込みを行ってもモードは維持され、その時点のカウンタはクリアされます。上限値、エラーボディ、起動時の `--rate-limit` / `CALENDARPIT_RATE_LIMIT` オプションについては、[起動と設定](/ja/running/#calendar-api-のレート制限)を参照してください。

### Test data

- **Storage** には、現在のストレージモードと SQLite ファイルのパス（または `:memory:`）が表示されます。
- **Fixtures & reset** では新しい [Fixture](/ja/fixtures/) を読み込めます。JSON を貼り付けるか **Open JSON file…** でファイルを選び、**Load fixture** を押します。読み込むと、ユーザー、カレンダー、イベント、OAuth クライアントがすべて置き換わり、OAuth 接続、リクエスト履歴、watch チャネルはすべて消去されます（リセット基準の Fixture は変わりません）。
- **Reset workspace** は起動時の Fixture を復元し、OAuth 接続、リクエスト履歴、watch チャネルをすべて消去します。
- **Current state** には、現在のワークスペースのデータが認証情報を除いた JSON で表示されます。

**Load fixture** と **Reset workspace** は実行前に確認ダイアログを表示します。自動テストからは[テスト制御 API](/ja/test-control/) で同じ操作を実行できます。

<AdminScreen
  view='test-data'

### OAuth clients

Fixture を再読み込みせずに、OAuth クライアントの追加・編集・削除を行えます。リダイレクト URI の追加やクライアントシークレットの変更に使います。クライアントを追加・編集しても、ユーザー、カレンダー、イベント、既存の OAuth 接続はそのまま維持されます（クライアントを削除した場合は、そのクライアントの接続が取り消されます）。詳しくは[アプリを接続する](/ja/connect/)を参照してください。
