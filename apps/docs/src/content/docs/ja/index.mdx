## Calendarpit が必要な理由

Google カレンダーと連携するアプリや AI エージェントの開発では、認証の設定やテスト用データの準備に手間がかかります。実際のカレンダーでは、同じ状態で何度も試すのも簡単ではありません。Calendarpit なら、Google の認証情報なしで、Fixture を使ってローカルで繰り返し試せます。

<Cards>
  <Card title="実際の Google に接続する場合">

    - Google アカウント、Cloud プロジェクト、OAuth の事前設定が必要
    - ネットワーク接続や共有の API クォータに左右される
    - 共有カレンダーのデータがテストごとに変わり、同じ状態を再現しにくい

  </Card>
  <Card title="Calendarpit を使う場合">

    - 認証情報なしでローカルのテストユーザーとしてログイン
    - 127.0.0.1 の単一プロセスで動き、外部通信が不要
    - Fixture とリセットで毎回同じデータからテストを開始

  </Card>
</Cards>

## 使い方の流れ

<Steps>

<Step>

### Calendarpit を起動

1 つのプロセスで、API、ローカル OAuth、管理画面が `http://127.0.0.1:4173` で動きます。

<Tabs items={["Homebrew","Docker"]} groupId='install'>
  <Tab value='Homebrew' forceMount>

```sh
brew install iktakahiro/tap/calendarpit
calendarpit serve
```

</Tab>
  <Tab value='Docker' forceMount>

```sh
docker run --rm -p 127.0.0.1:4173:4173 ghcr.io/iktakahiro/calendarpit:latest
```

</Tab>
</Tabs>

</Step>

<Step>

### 接続先を Calendarpit に向ける

Google SDK はそのまま使い、OAuth と API のエンドポイントだけを上書きします。`@googleapis/calendar` と `google-auth-library` の場合は次のとおりです。

```ts
const origin = 'http://127.0.0.1:4173';
const auth = new OAuth2Client({
  clientId: 'sample-app',
  clientSecret: 'local-sample-secret',
  redirectUri: 'http://127.0.0.1:4175/callback',
  endpoints: {
    oauth2AuthBaseUrl: `${origin}/oauth/authorize`,
    oauth2TokenUrl: `${origin}/oauth/token`,
  },
});
const api = calendar({ version: 'v3', auth, rootUrl: origin });
```

すべてのエンドポイントは[アプリを接続する](/ja/connect/)で、Python、Go、Kotlin、PHP、.NET の例は [SDK の使用例](/ja/sdks/)で説明しています。

</Step>

<Step>

### Fixture を使ってテスト

テストのたびに起動時の Fixture へリセットし、リクエストは管理画面で確認します。

```sh
curl -X POST http://127.0.0.1:4173/__calendarpit/reset \
  -H "Content-Type: application/json" \
  -d '{}'
```

</Step>

</Steps>
