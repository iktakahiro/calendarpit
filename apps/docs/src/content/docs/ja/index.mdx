## ローカルサーバーでテストする理由

<CardGrid>
  <Card title="実際の Google に接続する場合" icon="warning">

    - Google アカウント、Cloud プロジェクト、OAuth の事前設定が必要
    - ネットワーク接続や共有の API クォータに左右される
    - 共有カレンダーのデータがテストごとに変わり、同じ状態を再現しにくい

  </Card>
  <Card title="Calendarpit を使う場合" icon="approve-check">

    - 認証情報なしでローカルのテストユーザーとしてログイン
    - 127.0.0.1 の単一プロセスで動き、外部通信が不要
    - フィクスチャとリセットで毎回同じデータからテストを開始

  </Card>
</CardGrid>

## 使い方の流れ

<Steps>

1. **Calendarpit を起動する。** 1 つのプロセスで、API、ローカル OAuth、管理画面が `http://127.0.0.1:4173` で動きます。

   <Tabs syncKey='install'>
     <TabItem label='Homebrew'>
       <Code
         lang='sh'
         code={`brew install iktakahiro/tap/calendarpit\ncalendarpit serve`}
       />
     </TabItem>
     <TabItem label='Docker'>
       <Code
         lang='sh'
         code='docker run --rm -p 127.0.0.1:4173:4173 ghcr.io/iktakahiro/calendarpit:0.9.0'
       />
     </TabItem>
   </Tabs>

2. **アプリの接続先を切り替える。** Google SDK はそのまま使い、OAuth と API のエンドポイントだけを上書きします。`@googleapis/calendar` と `google-auth-library` の場合は次のとおりです。

   ```ts
   const origin = 'http://127.0.0.1:4173';
   const auth = new OAuth2Client({
     clientId: 'sample-app',
     clientSecret: 'local-sample-secret',
     redirectUri: 'http://127.0.0.1:4175/callback',
     endpoints: {
       oauth2AuthBaseUrl: `${origin}/oauth/authorize`,
       oauth2TokenUrl: `${origin}/oauth/token`,
     },
   });
   const api = calendar({ version: 'v3', auth, rootUrl: origin });
   ```

   すべてのエンドポイントは[アプリを接続する](/calendarpit/ja/connect/)で、Python、Go、Java、.NET の例は [SDK の使用例](/calendarpit/ja/sdks/)で説明しています。

3. **決まったデータでテストする。** テストのたびに起動時のフィクスチャへリセットし、リクエストは管理画面で確認します。

   ```sh
   curl -X POST http://127.0.0.1:4173/__calendarpit/reset \
     -H "Content-Type: application/json" \
     -d '{}'
   ```

</Steps>
