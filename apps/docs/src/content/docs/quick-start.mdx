## Start Calendarpit

Install and start with Homebrew:

```sh
brew install iktakahiro/tap/calendarpit
calendarpit serve
```

Or use Docker:

```sh
docker run --rm \
  -p 127.0.0.1:4173:4173 \
  -v calendarpit-data:/data \
  ghcr.io/iktakahiro/calendarpit:0.9.0
```

No Google account, Google Cloud project, external database, `.env` file, or provider credentials are needed. Both commands start the API, local OAuth server, and admin UI on the same origin. Compose and standalone downloads are covered in [Installation](/calendarpit/installation/).

## Open the admin UI

Open `http://127.0.0.1:4173`. The built-in fixture includes test users `alex` and `sam`, three calendars, and a planning event on `2026-10-19`. Changes made through the API appear automatically.

The CLI saves data in `.calendarpit/calendarpit.sqlite` under your current directory. Docker saves it in the mounted volume. For disposable tests, pass `--database :memory:` to the CLI or `-e CALENDARPIT_DATABASE=:memory:` to Docker. See [Storage and restarts](/calendarpit/storage/).

## Connect your app

Follow [Connect your app](/calendarpit/connect/) to point your SDK and OAuth flow at Calendarpit. Use [Fixtures](/calendarpit/fixtures/) to register local client credentials and exact callback URIs. The built-in `sample-app` / `local-sample-secret` credentials are public test values with callback `http://127.0.0.1:4175/callback`.

The optional source sample walks through approval, event creation, FreeBusy, watch delivery, and revocation. See the [development guide](https://github.com/iktakahiro/calendarpit/blob/main/docs/development.md) for setup. The sample is separate from the distributed server.
