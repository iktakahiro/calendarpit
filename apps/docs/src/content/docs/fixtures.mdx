A fixture is a JSON file that defines initial test data for Calendarpit: test users, calendars, events, and OAuth clients. Use a fixture to start your local server or test suite with a known dataset.

Setting explicit `id` values in your fixture gives your tests fixed user IDs, calendar IDs, event IDs, and OAuth client IDs. Your test assertions can check exact IDs instead of querying for generated values.

## Load a fixture at startup

Pass a fixture file path with the `--config` CLI flag or the `CALENDARPIT_CONFIG` environment variable. If you omit both, Calendarpit loads a built-in default fixture that is identical to `fixtures/default.json` in the repository (users `alex` and `sam`, calendars `alex-work`, `alex-personal`, and `sam-work`, one `planning` event, and the `sample-app` OAuth client).

Save the JSON example below as `calendarpit.fixture.json` and edit it for your test. Check prerequisites and publication status in [Installation](/calendarpit/installation/), then start from the directory containing the file:

```sh
calendarpit serve \
  --database :memory: --config ./calendarpit.fixture.json
```

Relative `--config` and `CALENDARPIT_CONFIG` paths resolve from the directory where you start Calendarpit.

In Docker, mount the existing file read-only and use its container path. This command uses POSIX shell syntax:

```sh
docker run --rm -p 127.0.0.1:4173:4173 \
  --mount "type=bind,source=$PWD/calendarpit.fixture.json,target=/fixtures/startup.json,readonly" \
  -e CALENDARPIT_CONFIG=/fixtures/startup.json \
  -e CALENDARPIT_DATABASE=:memory: \
  ghcr.io/iktakahiro/calendarpit:0.9.0
```

For Compose, add `./calendarpit.fixture.json:/fixtures/startup.json:ro` to the service's `volumes` and set `CALENDARPIT_CONFIG: /fixtures/startup.json` in `environment`. The host file must be readable by the container's non-root user. See [Run and configure](/calendarpit/running/) for startup options.

A startup fixture seeds only a **new, empty** database:

- In `--database :memory:` mode, the database is new on every process start, so the fixture always applies.
- When a SQLite file already contains saved data, Calendarpit does not apply the fixture and prints no warning. It loads the saved data (including per-user calendar-list settings and deleted-calendar tombstones) and the original reset baseline. The path you pass must still point to a readable JSON file, or startup fails. Its contents are not validated in this case. See [Storage and restarts](/calendarpit/storage/) for details.

To load a different fixture at runtime or reset back to the startup baseline between tests, use `POST /__calendarpit/fixtures` or `POST /__calendarpit/reset`. Both clear OAuth grants and tokens, per-user calendar-list settings, deleted-calendar tombstones, watch channels, deliveries, request history, sync tokens, and notifications; reset still restores the startup fixture (returning default calendar-list entries with their startup etags). `GET /__calendarpit/state` omits client secrets, calendar-list settings, and tombstones, and cannot be reloaded as a fixture. See [Test control API](/calendarpit/test-control/).

## Root structure and example

The root value of a fixture file must be a JSON object. It accepts four optional array keys: `users`, `calendars`, `events`, and `clients`. An empty object (`{}`) is a valid empty fixture.

Each key, if present, must be an array (`"<key> must be an array."`). Any other key on the root object or inside a user, calendar, event, or client entry fails validation (`"Unsupported field: <key>"`, reason `unsupportedFeature`).

```json
{
  "users": [{ "id": "alex", "name": "Alex", "email": "alex@example.test" }],
  "calendars": [
    {
      "id": "work",
      "userId": "alex",
      "summary": "Work",
      "timeZone": "Asia/Tokyo",
      "primary": true
    }
  ],
  "events": [
    {
      "id": "meeting",
      "calendarId": "work",
      "summary": "Planning",
      "start": { "dateTime": "2026-10-19T10:00:00+09:00" },
      "end": { "dateTime": "2026-10-19T11:00:00+09:00" }
    }
  ],
  "clients": [
    {
      "id": "sample-app",
      "secret": "local-sample-secret",
      "redirectUris": ["http://127.0.0.1:4175/callback"]
    }
  ]
}
```

## ID rules and validation

IDs are optional for users, calendars, events, and clients. A user that owns calendars, and a calendar that contains events, needs an explicit `id` so that other entries can refer to it.

- **Allowed characters**: ASCII letters, digits, `@`, `.`, `_`, and `-` (`^[a-zA-Z0-9@._-]{1,128}$`), up to 128 characters. An empty, whitespace-only, or non-string `id` fails with `"id must be a nonempty string."`. A nonempty string that breaks the pattern fails with `"Invalid ID."`. IDs from 129 to 10,000 characters fail with `"Invalid ID."`; longer values fail with `"id must be a nonempty string."`.
- **Reserved ID**: `primary` is reserved and cannot be used as an ID (fails with `"Invalid ID."`).
- **Uniqueness**: IDs within `users`, `calendars`, and `clients` must each be unique (`"Duplicate fixture ID."`). Event IDs must be unique within each calendar (`"Duplicate event ID."`); the same event ID can appear in different calendars.
- **Generated IDs and baseline capture**: When an `id` is omitted, Calendarpit generates a UUID. Generated IDs and initial event metadata (`created`, `updated`, `etag`) are captured in the startup reset baseline at seed time, so repeated calls to `POST /__calendarpit/reset` reproduce the same data. SQLite preserves that baseline across process restarts; in `:memory:` mode, every new process generates fresh UUIDs and timestamps.

Validation is atomic. Every owner and calendar reference must exist in the fixture. If any fixture rule fails, Calendarpit stops at the first error: at startup with a new database, the process prints `Calendarpit: <message>` and exits with code `1`; on `POST /__calendarpit/fixtures`, it returns `400` (`invalidParameter` or `unsupportedFeature`) and leaves existing data unchanged.

## Section reference

### `users`

Defines test users that can approve access in the consent page and own calendars.

| Field   | Required | Default        | Rules                                                                                           |
| ------- | -------- | -------------- | ----------------------------------------------------------------------------------------------- |
| `id`    | Optional | Generated UUID | 1–128 chars matching `[a-zA-Z0-9@._-]`; not `primary`. Unique across `users`.                   |
| `name`  | Required | —              | Nonempty string up to 10,000 characters.                                                        |
| `email` | Required | —              | Nonempty string up to 10,000 characters matching `^[^\s@]+@[^\s@]+$` (else `"Invalid email."`). |

### `calendars`

Defines calendars owned by fixture users. Every user that owns calendars must have **exactly one** calendar with `"primary": true` (else `"Each user with calendars must have exactly one primary calendar."`). A single calendar without `"primary": true` fails validation. Users without calendars are allowed; for those users, the `primary` calendar alias returns `404`.

| Field      | Required | Default        | Rules                                                                             |
| ---------- | -------- | -------------- | --------------------------------------------------------------------------------- |
| `id`       | Optional | Generated UUID | 1–128 chars matching `[a-zA-Z0-9@._-]`; not `primary`. Unique across `calendars`. |
| `userId`   | Required | —              | Must match a user `id` in `users` (else `"Unknown calendar owner."`).             |
| `summary`  | Required | —              | Nonempty string up to 10,000 characters.                                          |
| `timeZone` | Optional | `"UTC"`        | Valid IANA time zone name (else `"Invalid IANA time zone."`).                     |
| `primary`  | Optional | `false`        | Boolean (else `"primary must be boolean."`).                                      |

Seeded calendars start on their owner's calendar list with default settings (`selected: true`, `colorId: "1"`). When you later modify calendars or users through the management API (see [Test control API](/calendarpit/test-control/)):

- Deleting a primary calendar selects the first remaining owned calendar that is still on the calendar list, or the first remaining owned calendar when every remaining calendar was removed from the list. The chosen calendar is put back on the list if needed, keeping its other list settings.
- Setting `"primary": true` on another calendar transfers the flag atomically and puts that calendar back on the calendar list with its other settings kept.
- Deleting a calendar drops its list settings and records a deleted-calendar tombstone (`deleted: true` with default list settings when `showDeleted=true`). A deleted primary calendar's tombstone keeps `primary: true`. Recreating a calendar with a previously deleted ID clears that tombstone and any saved list settings. Deleting a user revokes their OAuth grants (stopping their watch channels) and removes their calendars, events, and list settings without adding tombstones.

### `events`

Defines initial events. Fixture events accept the Calendar API event fields and value validation (see [Calendar API compatibility](/calendarpit/compatibility/) and [Events, recurrence and time](/calendarpit/recurrence/)), plus `calendarId`. Read-only fields (`organizer`, `creator`, `iCalUID`, `recurringEventId`, `originalStartTime`) may be set, and `conferenceData` does not need `conferenceDataVersion`. The request-only field `attendeesOmitted` is rejected (`"Unsupported field: attendeesOmitted"`). Seeding does not run the side effects of an API insert: attendees do not receive invitation copies in their own calendars, and a `conferenceData.createRequest` does not generate a meeting link.

| Field                                                                      | Required | Default                                                                                                                                            | Rules                                                                                                                                                                                                                                                                             |
| -------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `calendarId`                                                               | Required | —                                                                                                                                                  | Must match a calendar `id` in `calendars` (else `"Unknown event calendar."`).                                                                                                                                                                                                     |
| `id`                                                                       | Optional | Generated UUID                                                                                                                                     | 1–128 chars matching `[a-zA-Z0-9@._-]`; not `primary`. Unique within the calendar.                                                                                                                                                                                                |
| `start`, `end`                                                             | Required | —                                                                                                                                                  | Event start and end (`dateTime` or all-day `date`), same rules as the Calendar API.                                                                                                                                                                                               |
| `organizer`, `creator`, `iCalUID`, `recurringEventId`, `originalStartTime` | Optional | Calendar owner (`organizer`, `creator`), `<id>@calendarpit.local` (`iCalUID`), none (`recurringEventId`, `originalStartTime`; set both or neither) | Read-only in normal API requests, but may be set in fixtures (for example, to seed an external organizer or stored recurring exceptions). Setting only one of `recurringEventId` or `originalStartTime` fails with `"Instances require recurringEventId and originalStartTime."`. |
| `sequence`                                                                 | Optional | `0`                                                                                                                                                | Non-negative integer (else `"Invalid sequence."`).                                                                                                                                                                                                                                |
| `created`, `updated`, `etag`                                               | Ignored  | Generated at seed time                                                                                                                             | Provided values are ignored and generated when the fixture is seeded.                                                                                                                                                                                                             |

### `clients`

Defines OAuth clients for [Local OAuth](/calendarpit/oauth/). There is no `scopes` field per client; any client may request any supported scope.

| Field          | Required | Default        | Rules                                                                                                                                                     |
| -------------- | -------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`           | Optional | Generated UUID | 1–128 chars matching `[a-zA-Z0-9@._-]`; not `primary`. Unique across `clients`.                                                                           |
| `secret`       | Required | —              | Nonempty string up to 10,000 characters.                                                                                                                  |
| `redirectUris` | Required | —              | Nonempty array of absolute `http` or `https` URLs (up to 10,000 characters each) without fragments or credentials. Matched exactly at `/oauth/authorize`. |
