When a request fails, Calendarpit returns an explicit status code and error message instead of silently ignoring unsupported fields or parameters.

Open **API history** (`http://127.0.0.1:4173/history`) in the admin UI to inspect the latest 200 Calendar API and OAuth exchanges. Each entry records the HTTP method, path, status code, headers, and masked request and response bodies. Use the **Errors** toggle to filter for responses with status `400` or higher.

## Error response formats

Calendar API routes (`/calendar/v3/*`), `/userinfo`, and management API routes (`/__calendarpit/*`) return the Google API error envelope:

```json
{
  "error": {
    "code": 404,
    "message": "Event not found.",
    "errors": [
      {
        "domain": "calendarpit",
        "reason": "notFound",
        "message": "Event not found."
      }
    ]
  }
}
```

- `domain` is `"calendarpit"` on all top-level errors. Per-calendar errors inside a `freebusy.query` response use `"domain": "global"`.
- `401` responses include the `WWW-Authenticate: Bearer` header.
- `400` validation errors without a more specific reason use `"reason": "invalidParameter"`.

OAuth routes (`/oauth/*` and `/oauth2/*`) return the OAuth error format. Most errors are HTTP `400`. Unimplemented paths return `501`, too many pending consent requests return `429`, and a cross-origin consent submission returns `403`:

```json
{
  "error": "invalid_grant",
  "error_description": "Invalid, expired, or mismatched authorization code."
}
```

Validation errors on `GET /oauth/authorize` are returned directly in the browser as HTTP `400` JSON. Calendarpit does not redirect invalid authorization requests back to `redirect_uri`.

## Starting Calendarpit

CLI startup failures print `Calendarpit: <message>` to `stderr` and exit with code `1`. For Docker, inspect the server output with `docker compose logs calendarpit`.

| `501 unsupportedFeature` on `/oauth2/...` or `/oauth/tokeninfo`        | Your SDK is calling Google's default OAuth paths (`/oauth2/v4/token`, `/oauth2/v3/userinfo`, or `/oauth/tokeninfo`).                                                                                                                                    | Override the endpoints explicitly to `/oauth/authorize`, `/oauth/token`, `/oauth/revoke`, and `/userinfo`.                                           |

Changing `SAMPLE_PORT` from `4175` also causes a mismatch with the built-in `sample-app` client.      | Copy the exact `redirect_uri` string into `clients[].redirectUris` in your fixture.                                                                  |
| `invalid_client`: `Unknown client.`                                    | `client_id` is not registered in the fixture, or `POST /oauth/token` was sent with a JSON body instead of `application/x-www-form-urlencoded` (which returns `unsupported_grant_type` if the client authenticates with HTTP Basic).                     | Register the client in your fixture and send token requests as `application/x-www-form-urlencoded`.                                                  |
| `invalid_client`: `Invalid client secret.`                             | `client_secret` is missing or wrong. Calendarpit requires a client secret on every token request, including PKCE flows.                                                                                                                                 | Send the matching `client_secret` in the form body or via HTTP Basic authentication.                                                                 |
| `invalid_grant`: `Invalid, expired, or mismatched authorization code.` | The code is older than 60 seconds, was already used once, `redirect_uri` is missing or differs from `/oauth/authorize`, the client differs, the connection was revoked, or the server restarted.                                                        | Exchange the code once within 60 seconds with the exact `redirect_uri` and client used at `/oauth/authorize`.                                        |
| `invalid_grant`: `Invalid PKCE verifier.`                              | `code_verifier` does not match the `S256` `code_challenge` or is not 43–128 characters of `[A-Za-z0-9._~-]`.                                                                                                                                            | Send the original verifier string used to compute the `S256` challenge.                                                                              |
| `invalid_grant`: `Invalid refresh token.`                              | The connection was revoked, the user was deleted, the workspace was reset or a fixture was loaded, an in-memory server restarted, or the token belongs to another client.                                                                               | Run the authorization flow again to create a new connection.                                                                                         |
| `state` is missing or mismatches on callback                           | `state` was omitted from `/oauth/authorize` (it is echoed only when sent), or your app started on `localhost` and received the callback on `127.0.0.1` (if your app keeps `state` in a cookie, a callback on a different hostname does not receive it). | Pass `state` on `/oauth/authorize` and use the same hostname (`127.0.0.1` or `localhost`) for both your app and its `redirect_uri`.                  |
| `invalid_scope`: `Unsupported or missing scope.`                       | `scope` is empty or includes an unsupported scope (such as `calendar.events.owned` or Drive scopes).                                                                                                                                                    | Request only [supported scopes](/calendarpit/oauth/).                                                                                                |
| `invalid_scope`: `Refresh scope changes are unsupported.`              | A `refresh_token` request included a `scope` parameter that does not exactly match the original grant string (including scope order).                                                                                                                   | Omit `scope` when refreshing a token.                                                                                                                |
| No `refresh_token` in the token response                               | `access_type=offline` was not sent on `/oauth/authorize`, or the response is from a `refresh_token` grant (refresh responses return a new `access_token` only; the original refresh token stays valid).                                                 | Add `access_type=offline` to `/oauth/authorize` and keep the initial `refresh_token`.                                                                |
| `unsupported_feature` on `/oauth/authorize`                            | The request included `prompt=none`, `include_granted_scopes=true`, or an unsupported parameter such as `nonce`, `login_hint`, `hd`, or `enable_granular_consent`.                                                                                       | Remove unsupported parameters and use interactive consent (`prompt=consent` or `prompt=select_account`).                                             |
| `invalid_request`: `PKCE requires S256.` / `Missing PKCE challenge.`   | `code_challenge` was sent without `code_challenge_method=S256` (including `plain`), `code_challenge_method` was sent without `code_challenge`, or `code_challenge` is not 43 base64url characters.                                                      | Use `code_challenge_method=S256` with a 43-character base64url challenge.                                                                            |
| `invalid_request`: `Consent request expired or already used.`          | The consent page was left open longer than 5 minutes, submitted twice, or the server restarted before submission.                                                                                                                                       | Start a fresh authorization request at `/oauth/authorize`.                                                                                           |
| `429 rateLimitExceeded`: `Too many pending consent requests.`          | 1,000 consent requests are already pending (each expires after 5 minutes; usually caused by a loop in tests).                                                                                                                                           | Complete or stop opening consent requests, or reset the workspace.                                                                                   |

## Management API

| Symptom                                                                                  | Likely cause                                                                                                                                                                           | Fix                                                                                                                                                              |
