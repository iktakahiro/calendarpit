title: Calendarpit
description: Develop calendar integrations locally, with predictable state and no real Google account.
---

Calendarpit is a local development and test server for calendar integrations.
It implements a documented subset of Google Calendar, OAuth consent and tokens,
and event watch callbacks. Chronock is the first intended consumer, not a dependency.

The admin UI edits users, calendars, and events; shows connections, watch delivery
results, and masked API history; and loads/resets fixtures. One Bun process serves
both API and UI, with local SQLite persistence, optional memory mode for E2E, and no external database server.

## Try the workflow

1. Run `bun run dev` and open `http://127.0.0.1:4173`.
2. Run `bun run sample:dev` and open `http://127.0.0.1:4175`.
3. Connect the sample, choose a local test user, and approve access.
4. Select a calendar, start a watch, and create an event.
5. Inspect the event in the admin UI and busy intervals in the sample.
6. Update/delete the event, revoke access, and reconnect.
7. Reset to startup fixtures and repeat.

The included Google SDK integration test exercises this sequence twice against
real local HTTP servers and blocks outbound SDK calls to non-loopback hosts.
No real Google credentials are required.

See [Development](/development), [SDK integration](/integration), and
[Fixtures and test control](/fixtures) to get started. Read
[Compatibility](/compatibility) for supported fields, scopes, and explicit errors.
Docker startup validation, release publication, and integration with Chronock
remain follow-up work.
